# assets/ —— 美术资产目录

本目录是**贴图/图标的真实来源**（T-A2 建立的通道）。在此之前全部贴图由
`game/client/src/atlas.cpp` 在运行时程序化生成，改一块泥土的颜色要改 C++ 再编译；
现在放一个 PNG 文件即可，**不需要改代码、不需要重新编译**。

---

## 1. 目录布局（冻结，不要随意改）

```
assets/
├── CREDITS.md              ← 证据链（每条资产一行，见第 4 节）
├── README.md               ← 本文件：落笔规范
├── blocks/                 ← 方块贴图
│   └── <block_id>_<slot>.png      slot ∈ {top, side, bottom}
└── items/                  ← 物品图标（通道已建，暂无内容）
    └── <item_id>.png
```

命名示例：`blocks/dirt_side.png`、`blocks/grass_block_top.png`、`blocks/grass_block_side.png`、
`items/sunroot.png`。

**为什么用字符串 id 而不是编号**：数字 id 由注册顺序决定，会随内容卡漂移；
字符串 id 稳定，与 `BlockRegistry::string_of()` 及代码里的写法一致。
`blocks/` 与 `items/` 的文件名必须**逐字**匹配代码里的 id，写错等于没放
（不报错，静默回退到程序化贴图）。

方块的三个 slot 就是网格化（mesher）的三个槽位：

| slot | 文件名后缀 | 用于 |
|---|---|---|
| 0 | `_top` | 方块顶面 |
| 1 | `_side` | 四个侧面 |
| 2 | `_bottom` | 方块底面 |

## 2. 文件规格（硬性）

| 项 | 要求 | 不符时 |
|---|---|---|
| 格式 | **PNG**（按文件头判断，改扩展名没用） | 拒绝 + 日志 WARN + 回退程序化贴图 |
| 尺寸 | **正好 16×16 像素** | 同上（**不会缩放**，见下） |
| 内容 | 8/16 位任意色彩类型，一律解码为 RGBA8 | — |
| 朝向 | PNG 的**第一行 = 方块面的上边** | — |

- **不缩放、不拉伸**：像素风缩放会引入插值，还会掩盖落笔尺寸错误。
  尺寸不对就是不对，游戏会告诉你。
- **上下不要画反**：PNG 第 0 行（图像顶部）贴在方块面的上沿。
  拿不准就画一个上下不对称的图案试一次。
- **透明**：需要透光/半透的贴图（水、玻璃、树叶）直接写 alpha；
  不透明贴图 alpha 填 255。

## 3. 回退语义（当前的实际状态）

对每一个 `(方块, slot)`：

```
assets/blocks/<id>_<slot>.png 存在且是合法 16×16 PNG  →  用文件的像素
否则                                                →  用代码里的程序化图案
```

- **文件不存在 = 正常状态**，不是错误，不会刷日志。
- `assets/` 整个目录不存在也能正常启动（全新检出就是这个状态）。
- **改动是逐个瓦片生效的**：只放 `dirt_side.png`，就只有泥土侧面变；
  其余方块、其余面、以及开采裂纹动画都保持原样。
- **不做热重载**：贴图在启动时读一次，改完文件要重启游戏。

## 4. 证据链（每条资产必填）

每放一个文件，必须在 `CREDITS.md` 里加一行（表头已建好，字段固定）：
`文件 / 来源 / 工具 / 提示词摘要 / 日期 / 人工后处理`。

## 5. 合规红线（三条硬规则，逐字引自 `docs/05-development-process.md` §2）

> ### 美术资产三条硬规则（AI 生成相关，2026-09-18 立）
>
> 1. **AI 输入禁止含 MC 资产**：不得把原版贴图/截图/官方美术喂给模型做"参考重绘"
>    （`docs/04` 红线 2：改色/翻转/重采样也算衍生）。要参考只喂**文字描述**。
> 2. **提示词不得点名 MC**：不得出现 "Minecraft-style" 之类。这是红线 5（观感不逐项对齐）的执行手段。
> 3. **证据链照旧**：`assets/CREDITS.md` 每条须写 `工具 + 提示词摘要 + 日期 + 人工后处理`。
>    AI 生成不豁免留痕——因为它更易产出接近原版的东西，更该留痕。

完整条文见 `docs/05-development-process.md` §2 与 `docs/04-legal-compliance.md`
「AI 生成资产」节；本文件只引述，如有冲突以那两处为准。
