note on the contrast row (x=64.5, released = 0):
  a FRESH session's resident set only ever holds (a) the startup 5x5 around the
  origin and (b) the player's own generation window, so a 4-chunk step in a new
  session has nothing behind it to release - the trailing chunks were never
  generated in that session. On this machine the release event is therefore
  observable when the player leaves an area the session had loaded, which is
  what the 300-block displacement does (p4b): released 25 chunk(s).
  The quantitative band behaviour (2 chunks free, beyond the band releases the
  trailing columns, zero hysteresis churns) is asserted in
  tests/test_chunk_streaming.cpp, whose request-level entry point is the same
  stream() the client drives.
