## 0. 这份规格对齐什么、不对齐什么

**对齐的是风格类别**：16×16 网格、低饱和、像素风、硬边无插值。这是一类抽象的视觉语言，
不属于任何具体作品。

**不对齐的是具体表达**：不得参照任何既有游戏的某块具体纹理的构图、配色、纹样来画。
本文件全篇不写"某方块像某某的某某"，所有图案描述都是**从材质本身出发**的
（土是颗粒、石是斑驳、木是纤维、水是层流）。

## 1. 画布与网格

| 项 | 规定 |
|---|---|
| 画布 | **正好 16×16 像素**，不多不少 |
| 落点 | 每个像素必须落在**整格**上；不存在"半格""1.5 px 宽"的线条 |
| 抗锯齿 | **禁止**。不得出现任何插值出来的中间灰边、柔化边缘、羽化 |
| 缩放 | **禁止**。导出后不得再缩放/重采样；16×16 就是交付尺寸 |
| 色彩类型 | 导出 8 位 RGBA（见 §6 alpha 约定）；位深不符不会被拒，但一律按 RGBA8 解码 |
| 文件格式 | PNG（`assets/README.md` §2；尺寸不符**静默回退**程序化贴图，不报错） |

**判定方法**：把图放大到 1600% 看，任何"两个色块之间夹着第三种颜色的过渡像素"即为违规。
本清单第 8 项把它列为交付前的必查项。

## 3. 低饱和原则（可执行的判定）

**判定式**（HSV 的 S，逐色计算；`S = (max−min)/max`，V=0 时 S=0）：

```
每一张贴图上出现的每一个颜色：  S ≤ 0.50
例外：矿石点缀色 O0–O4 允许 S ≤ 0.50（同上，不另开口子）
```

- 本批 32 色实测：最高 `A1 水 0.480`，全部 ≤ 0.50 ✓（导出脚本启动时自检并打印该值）。
- **明度不设上限**：雪 `#E2E6EC`、UI 高亮 `#E6E2D4` 允许接近白；低饱和不等于灰暗。
- **为什么是 0.50**：§2.2 里原色板 20 个主色中，非水/铜/金的 17 个实测 S 范围是
  0.038–0.466——0.50 是"在这些已被接受的中性材质色之上留一点余量"的经验线，
  不是任意值。将来若要引入"鲜艳"资产（如发光矿石），须**先改本节的例外条款**，
  不得在贴图里悄悄破线。

## 4. 构图语言

目标：不同材质可辨识，但**看起来是同一个世界画的**。四条约定：

1. **噪点粒度统一为 1–3 px 的簇**。土/沙/石用 1–2 px 的散点簇（不做 1 px 孤立胡椒点，
   放大后像脏点）；叶用 2–3 px 的不规则簇。全项目**不得出现 4 px 以上的实心色块**
   （那会变成"色块"而不是"纹理"）。
2. **方向性纹理只走两个方向**：**竖直**（原木树皮、水流侧壁）或**水平**（木板、水面的波带）。
   禁止斜向条纹做材质本身——斜向留给 §4.4 的高光。
3. **边缘处理**：不画描边。方块之间的区分靠**面明暗**（引擎侧已做：顶亮/侧中/底暗）与
   相邻材质的色相差，不靠勾轮廓线。
   > 例外只有玻璃：G0 是**结构性边框**（表达"这是一块镶在框里的板"），不是轮廓线。
4. **高光**：每张贴图最多一处高光，且必须是**斜向 45° 的 2 px 宽带**
   （玻璃的 G1h）或**单像素亮点**（矿石的 S3 反光，每个矿簇最多 1 px、每面最多 1 处）。
   高光的作用是"材质反光"，不是"画个装饰"。
5. **禁止的规则形**：不得出现完美的方格棋盘、等距平行线、居中的十字/圆点——
   这类规则图案在 16×16 上极易读成"图标"而不是"材质"。

## 5. 三面关系（`_top` / `_side` / `_bottom`）

一个方块的三个 slot 各自独立成文件（见 `assets/README.md` §1）。约定：

| 情形 | 约定 | 本批实例 |
|---|---|---|
| **有明确朝向的材质** | 侧面表现"过渡/断面"，顶底表现"材质本体" | `grass_block`：侧面 = 顶部 3–5 px 参差绿边 + 下部泥土；底面 = 纯泥土；顶面 = 纯草 |
| **纤维类** | 侧面 = 顺纤维方向的竖纹；顶底 = 纤维的横截面 | `log`：侧面竖纹 + 一处节疤；顶面 = 年轮同心环；底面 = 年轮 + 一道径向裂 |
| **加工类** | 侧面表达"排列方向"，顶底表达"拼合缝" | `planks`：侧面竖排四块 + 错缝接头；顶/底横排四块 + 竖向端接头（顶底接头位置不同） |
| **均质类** | 三面同源但**排布不同**：同一份手稿用三个不同的行序输出 | `leaves`（三面行序不同）、`dirt`/`stone`/`sand`（三份独立手稿） |
| **三面相同** | **仍须三份文件**（`assets/README.md` §1：3 个 slot 是网格化的三个槽位）。用"同一来源三份输出"的方式，且**行序/接缝位置互相错开**，避免三面出现同一处特征 | `leaves` 即按此办理 |
| **可复用** | 允许一个方块的面直接复用另一个方块的稿（如 `grass_block_bottom` = `dirt_bottom`），但**落盘仍是两个文件**，并在 CREDITS 里写明"稿源" | `grass_block_bottom` |

> ⚠ 引擎侧事实（不是本规格的规定，但影响可见性）：
> 网格化对**半透方块跳过底面**（`engine/render/src/mesher.cpp:198`），
> 即 `water/glass/leaves` 的 `_bottom` 文件**目前不会出现在画面上**。
> 本批仍按"三面齐全"交付，以备该约束将来放开。

## 6. 透光资产的 alpha 约定

| 资产 | alpha | 说明 |
|---|---|---|
| 一切不透明资产 | **255，全图一律 255** | 包括 `leaves`（本批按不透明叶丛处理，不做镂空） |
| `water` 主色 A1 | **170** | 水体主色；水下地形可见 |
| `water` 浅色带 A2 | **190** | 波光带，比主色更"实"一点，形成层流感 |
| `glass` 面 G1 | **44** | 极透，只留一层薄色 |
| `glass` 高光 G1h | **120** | 高光比面实，才看得出"反光" |
| `glass` 边框 G0 | **210** | 边框是实体感的来源，接近不透明 |

规则：

1. **alpha 只取自上表**，不逐像素手调；半透资产的 alpha 是**材质属性**不是绘画变量。
2. 半透资产**不得靠 alpha 做抗锯齿**——半透边缘仍然是硬边。
3. 半透资产的 RGB 按 **sRGB 直给**（导出时不做预乘 alpha）；渲染侧是
   `GL_SRC_ALPHA / GL_ONE_MINUS_SRC_ALPHA`。
4. 水的 RGB 与 alpha 一起表达深度：深色带=A1（"深"），浅色带=A2（"浅"），不必再加第三档。
