## 1. 生物 AI（重点）

> 本节是本卡最重要的一节。目标是让读者能据此**设计出 AI 结构**并**实现典型行为**。
> 只描述机制结构与参数，**不穷举 70+ 种生物各自的 AI**。

### 1.1 两套并存的 AI 架构

基准版本里生物 AI **不是一套**，而是两套并存（来源：<https://minecraft.wiki/w/Mob_AI> ，
访问 2026-09-17，§Goals / §Brain）：

| | **目标栈（Goal Stack）** | **脑（Brain）** |
|---|---|---|
| 使用者 | 较早已存在的生物（僵尸、骷髅、蜘蛛、苦力怕、牛、羊、猪、鸡等） | 较新/较复杂的生物（猪灵、悦灵、监守者、村民、山羊、嗅探兽等） |
| 组织方式 | 一张**按优先级排序的目标列表**，每个目标可独立开关 | **感知器 → 记忆 → 活动 → 行为**四层 |
| 并发性 | 低优先级目标可同时运行（如"看"与"游荡"并行） | 同活动内按优先级尝试启动行为；`core` 活动常驻后台 |
| 复杂度 | 低，易实现 | 高，数据驱动 |

**给 OpenCraft 的建议**：M2c 首发名单（`docs/01` §6：牛/羊/猪/鸡/鱼/狼/铁傀儡 + 僵尸/骷髅/蜘蛛/爬行者等价物）
**全部落在目标栈这一侧**。因此 **M2c 实现目标栈即可**，脑系统可留到 M4+ 需要复杂生物时再说。
这是本节能给出的最有价值的收敛结论 —— 不要一上来就做行为树/黑板那套重型设施。

### 1.2 目标栈：结构与调度

#### 1.2.1 结构（原创画法，不对应任何具体类名）

```
                 ┌──────────────────────────────────────┐
   每 tick  ───► │  按优先级从高到低扫描目标列表         │
                 │  每个目标维护 started / running 状态  │
                 └──────────────┬───────────────────────┘
                                │
              ┌─────────────────┼─────────────────────┐
              ▼                 ▼                     ▼
       canUse() 为真？   continueUse() 为真？   已启动且条件失效
              │是               │是                    │
              ▼                 ▼                     ▼
          start()           tick()                stop()
```

每个目标提供四个回调：`canUse`（能否开始）、`start`（开始）、`continueUse`（能否继续）、
`stop`（结束）。调度器每 tick 从**最高优先级**往低扫：
- 未运行的目标若 `canUse` 为真则 `start`；
- 已运行的目标若 `continueUse` 为假则 `stop`；
- **低优先级目标不会因为高优先级在运行而自动停止** —— 是否互斥靠目标自身的 `canUse` 表达。

#### 1.2.2 优先级互斥靠什么表达（实现要点）

优先级**数字越小越高**。wiki 给出的僵尸目标表可作模板
（来源：<https://minecraft.wiki/w/Mob_AI> §Lists of mob goals，访问 2026-09-17）：

| 优先级 | 目标 | 备注 |
|---|---|---|
| 1 | 反击（Revenge） | 攻击伤害过自己的实体 |
| 2 | 主动选目标 — 玩家 | |
| 2 | 攻击（Attack） | 攻击当前目标 |
| 3 | 主动选目标 — 铁傀儡 | |
| 3 | 主动选目标 — 商人 | |
| 4 | 破坏蛋 | |
| 5 | 主动选目标 — 海龟 | |
| 7 | 大范围游荡 | |
| 8 | 环视 / 注视实体 | |

注意 **优先级 2 有两个目标、8 有两个目标** —— 说明同优先级可共存。
wiki 明文："生物尝试执行它能执行的**最低**优先级目标"这句话的准确含义是：
**高优先级目标一旦可启动就会抢先，但它不清除低优先级目标**；
互斥是通过让低优先级目标的 `canUse` 去读"当前是否已有攻击目标"这类状态来实现的。

> ⚠ **实现陷阱**：如果把目标栈实现成"每 tick 只执行第一个 `canUse` 为真的目标"，
> 则僵尸永远只会反击，不会游荡也不会环视 —— 行为会明显不对。
> 正确做法是"每 tick 扫描全表，凡 `canUse` 为真且未运行的都启动"，用 `canUse` 内部的状态
> 读取来表达互斥。

### 1.3 感知（Perception）

#### 1.3.1 三个距离概念必须分开（最容易做错的一处）

| 概念 | 含义 | 基准值 |
|---|---|---|
| **追踪距离（follow_range）** | 目标一旦锁定后，超出此距离就放弃追踪 | 属性默认值 **32**；僵尸系 **35**；骷髅/蜘蛛/其他 **16**；末影人 **64**；劫掠兽/狐狸/猪灵? **32**；监守者/风弹怪 **24**；**其余生物 16** |
| **感知/察觉距离** | 玩家进入此距离生物才"注意到"并开始游荡/盯人 | **16**（多数生物；wiki：多数生物能察觉 16 格内的玩家，部分能看得更远） |
| **引诱距离（tempt_range）** | 手持繁育物时生物开始跟随的距离 | 属性默认 **10**；牛/羊/猪/鸡等被动生物均为 **10** |

> ⚠ **注意 wiki 自身的口径冲突**：`follow_range` 属性信息框写的默认值是 **32**，
> 但其"其余生物"一行写的是 **16**，且 `<https://minecraft.wiki/w/Mob>` 正文说
> "多数生物能察觉 16 格内的玩家"。**这两者不是同一个东西**（前者是放弃追踪的距离，
> 后者是察觉距离），实现时务必分成两个字段，不要共用一个常量。
> 骷髅页明文"看到 16 格内的玩家后追击"—— 即骷髅的**察觉 = 16**，
> 而它的 `follow_range` 也在 16 档；僵尸的**察觉 = 35**（wiki 明文"从 35 格外追击玩家"），
> `follow_range` = 35 档。这两个生物恰好自洽，但**不能据此推出"察觉 = follow_range"**。

（来源：<https://minecraft.wiki/w/Attribute> §Mob Follow Range；
<https://minecraft.wiki/w/Zombie> §Attacking the player；
<https://minecraft.wiki/w/Skeleton> §Behavior；
<https://minecraft.wiki/w/Spider> §Behavior；
<https://minecraft.wiki/w/Mob> §Behavior。均访问 2026-09-17。）

#### 1.3.2 视线判定

- 生物**不能透过大多数固体方块**看见目标，包括冰、玻璃、高草、玻璃板这类半透明方块
  （来源：<https://minecraft.wiki/w/Mob> §Behavior，访问 2026-09-17）。
- 感知的目标条件含一个显式布尔 `checkLineOfSight`；为真时要求
  **从生物眼睛到目标能连一条不与方块碰撞盒相交的直线**
  （来源：<https://minecraft.wiki/w/Mob_AI> §Targeting condition，访问 2026-09-17）。
  实现上就是一次 **DDA 体素射线**——与 `docs/03` §6 已有的"方块命中用 DDA voxel raycast"
  是同一套设施，可复用。

#### 1.3.3 感知的刷新频率

- 脑系统里，**感知器默认每 20 tick 扫一次**；个别感知器用不同的扫描率
  （如村庄次要点感知器 **40 tick**）。
- **首次执行会被随机延迟**一个 `[0, scanRate)` 的整数 tick 数，
  目的是打散多个感知器同帧触发（来源：<https://minecraft.wiki/w/Mob_AI> §Sensor，访问 2026-09-17）。

> **给目标栈实现者的建议**：即便 M2c 只做目标栈，也应把"目标选取"做成
> **每 20 tick（或每 N tick）一次、且带随机相位偏移**，而不是每 tick 全量扫描。
> 理由：① 与基准行为一致（避免生物"瞬间锁定"，观感生硬）；② 打散峰值开销。
> 这是本文能给出的、成本极低但对观感影响明显的一条。

#### 1.3.4 目标条件中的距离修正（可后置）

基准实现在距离判定上叠了一组乘性修正（来源：<https://minecraft.wiki/w/Mob_AI>
§Targeting condition，访问 2026-09-17）：潜行 **×0.8**；隐身且无盔甲 **×0.07**；
隐身有盔甲 **×0.175×p**；戴着对应生物头颅 **×0.5**；修正上限 **×10**。
判定式形如 `距离 > max(range × modifier, 2.0)` 则失败。

**M2c 建议**：首发只实现 **潜行 ×0.8** 与 **下限 2.0 格** 两条，隐身/头颅等到有对应内容再加。

### 1.4 寻路（Pathfinding）

#### 1.4.1 总体结构（原创画法）

```
   目标请求移动 → 导航系统计算路径 → 逐节点跟随 → 卡住检测 / 重算
        │                                  │
        │                         到达节点 → 推进下一节点
        │                         可直达   → 允许跳节点
        └─ 路径失效 / 被手动停止 → 路径结束
```

- 导航系统保存：**当前路径、移动速度、目的地**。每次 AI 更新时检查路径、推进已到达的节点、
  向移动控制发出移动指令（来源：<https://minecraft.wiki/w/Mob_AI> §Navigation，访问 2026-09-17）。
- 默认导航类型是**地面路径导航**；水生/飞行生物用各自的专用实现。
- 若生物**卡住**（一段时间没有足够位移），导航系统检测并停掉路径。

#### 1.4.2 代价值（这是寻路的核心，也是最容易做错的）

路径不是"最短"，而是**总代价最低**。每个可通行格有一个代价值（penalty），
生物倾向于走代价最小的路径；**−1 表示不可通行**。
来源：<https://minecraft.wiki/w/Mob_AI> §Pathfinding penalties，访问 2026-09-17。

| 代价类型 | 值 | 含义 |
|---|---|---|
| blocked | **−1** | 不可通行（多数完整固体方块） |
| fence / wall / 关闭的栅栏门 | **−1** | 不可通行 |
| lava | **−1** | 不可通行 |
| unpassable rail | **−1** | 不可通行（多数生物会避开铁轨，除非被推上去） |
| powder snow | **−1** | 不可通行 |
| damage - other（仙人掌、甜浆果丛） | **−1** | 不可通行 |
| closed wood/iron door | **−1** | 不可通行（关着的门） |
| **open（空气）** | **0** | 基准 |
| walkable / walkable door / trapdoor | **0** | 可走 / 能开的门 / 活板门、睡莲 |
| open door | **0** | 开着的门 |
| damage - cautious（凋零玫瑰、尖锥石） | **0** | 可走（不痛） |
| danger - fire / danger - other | **8** | **邻格**是火/岩浆/岩浆块/营火/仙人掌 |
| water / water border | **8** | 是水 / 邻格是水 |
| honey | **8** | 蜂蜜块 |
| breach water | **4** | 水格上方是空气（出水口） |
| damage - fire | **16** | 本格是火/岩浆/岩浆块/营火 |

**读法**：0 是"正常地面"；8 是"邻格有危险"（生物仍会走，但会绕）；16 是"本格就是危险"；
**−1 是"绝对不可通行"**。三者语义层级不同，实现时不要用同一个"是否可走"布尔吃掉。

**关键推论（wiki 明文）**：代价表的存在意味着生物**会为了避开高代价格而绕远路、甚至主动穿
过会受伤的格子**。wiki 给的示例是：僵尸猪灵去海龟蛋时，绕路穿过**凋零玫瑰**（代价 0，
"小心但可走"）而不是穿过岩浆（代价 −1，不可通行）—— 尽管它免疫岩浆伤害
（来源：<https://minecraft.wiki/w/Mob_AI> §Pathfinding penalties，访问 2026-09-17）。
**不要**用"是否会造成伤害"来判断可通行性，那会得到不同的行为。

#### 1.4.3 逐生物的代价覆盖（M2c 相关的几条）

部分生物覆盖默认值（来源同 §1.4.2）：

| 生物 | 覆盖项 | 值 | 效果 |
|---|---|---|---|
| 鸡 | water | **0** | 鸡不避水 |
| 鱼类 / 水生生物 | water | **0** | 水中正常寻路 |
| 动物类（animal） | damage - fire | **−1** | 动物绝不会走进火里 |
| 狐狸 | danger - other / damage - other | 0 | 不怕浆果丛 |
| 劫掠兽 | leaves | 0 | 可穿树叶 |

> ⚠ **`animal` 的 `damage-fire = −1` 是一条对被动生物很重要的规则**：
> 牛/羊/猪/鸡不会主动走进火与岩浆。若偷懒统一用"生物都会避火"，
> 则敌对生物（僵尸会追人进火）的行为就错了。建议把代价表做成
> **默认表 + 逐生物覆盖表**两层结构。

#### 1.4.4 陆上寻路的其余规则

来源：<https://minecraft.wiki/w/Mob_AI> §Pathfinding on land，访问 2026-09-17：

- 游荡时随机目标**每 tick 生成**，可在生物范围内的三维空间任意位置；
- 每个目标生成一条路径，生物取**代价最低**的那条；
- 若所有路径代价都过高、或没有代价 ≠ −1 的路径，**生物原地不动**直到找到路；
- 若目标点在方块内（含水中），**目标被上移到最近的空气格**。

> 最后一条有个 wiki 指出的副作用：游荡时随机点更可能落在生物**下方**的方块里，
> 再被上移到上方空气格 —— 因此生物游荡时**倾向于走向"下方方块最多"的位置**，
> 也就是**偏好待在地势较高/平坦处**。这是原版行为，不是 bug，实现时保留即可。

#### 1.4.5 水中 / 空中

- 水中寻路与陆地大致相同，但**除鱼和溺尸外，多数实体会在水面上下弹动**，
  因为水的代价高（8），它们更偏好陆地（来源同 §1.4.4）。
- 空中寻路同理，但能寻路到空气中的生物很少。

#### 1.5.7 逃跑（Flee）机制的通用参数

有一套独立于"受伤恐慌"的**畏惧逃跑**机制（来源：<https://minecraft.wiki/w/Mob_fleeing> ，
访问 2026-09-17）：

- 生物在**有视线**时**每 5 tick** 检查一次周围的畏惧源；
- 检测半径**逐畏惧源而异**（举例：8 格、15 格）；
- 逃跑时移动到**距畏惧源 4–15 格**的位置，然后恢复常规行为；
- 逃跑**通常成为最高优先级**，会打断交互与攻击；结束后多数会回到之前的行为。

已知畏惧关系（M2c 可能用到的）：骷髅系**怕狼**（被狼咬到后转为反击）；
苦力怕**怕猫/豹猫**；鱼类**怕玩家**。

> ⚠ `Mob_fleeing` 页带 `{{wip}}` 标记，且"逃跑时的速度倍率"wiki **未给数值**。
> **标"待校准"，不要自行发明**（见 §7 R-6）。

### 1.6 实现建议（不给代码，只给结构）

1. **先做目标栈，不做脑。** 首发名单全在目标栈侧。
2. **目标接口四回调**（`canUse`/`start`/`continueUse`/`stop`），每 tick 扫全表，
   互斥写在 `canUse` 里（见 §1.2.2 的陷阱）。
3. **感知与决策分离**：感知每 20 tick 跑一次 + 随机相位偏移，写入一个"感知快照"；
   目标每 tick 只读快照，不做射线。这样开销可控且行为与基准一致。
4. **寻路用带代价的网格搜索**（代价值见 §1.4.2），代价表做成**默认表 + 逐生物覆盖表**。
   不要用"是否造成伤害"当可通行性判据。
5. **距离字段至少三个**：察觉距离、放弃追踪距离、引诱距离（§1.3.1）。
6. **攻击判定用"碰撞盒外扩 + 视线"，不要用中心距**（§1.5.1）。

## 3. 经验升级与掉落

> `docs/research/01` §4 已含三段公式与总量参考（352 / 1395）。

### 3.1 升级所需经验（下一级）

记当前等级为 $L$，从 $L$ 升到 $L+1$ 所需 XP：

$$
\Delta(L) = \begin{cases}
2L + 7, & 0 \le L \le 15 \\[4pt]
5L - 38, & 16 \le L \le 30 \\[4pt]
9L - 158, & L \ge 31
\end{cases}
$$

**边界说明（PM 卡面要求补的部分）**：
分段是按**当前等级 $L$** 划的，不是按目标等级。wiki 原文标注为
"for levels 0–15 / 16–30 / 31+"（来源：<https://minecraft.wiki/w/Experience> §Leveling up，
访问 2026-09-17）。按此：

- $L=15$ 用第一式 → $2\cdot15+7 = 37$（升到 16）
- $L=16$ 用第二式 → $5\cdot16-38 = 42$（升到 17）
- $L=30$ 用第二式 → $5\cdot30-38 = 112$（升到 31）
- $L=31$ 用第三式 → $9\cdot31-158 = 121$（升到 32）

> ⚠ **与 `docs/01` §3 的写法差异**：`docs/01` 写成 `2L+7（0–15）/ 5L−38（16–30）/ 9L−158（31+）`，
> 与 wiki 一致；但 `docs/research/01` §4 的表格行显示 **Lv30 的增量是 107**
> （"| 30 || 1395 || 107"），而按第二式应为 **112**。
> **这两处不一致**，wiki 同页也同时给出了 1395 这个总量。
> 需 PM 裁定或实机校准（见 §7 R-3）。**本文不擅自修改任一处。**

### 3.2 总量（从 0 级到等级 $L$ 的累计 XP）

$$
T(L) = \begin{cases}
L^2 + 6L, & 0 \le L \le 16 \\[4pt]
2.5L^2 - 40.5L + 360, & 17 \le L \le 31 \\[4pt]
4.5L^2 - 162.5L + 2220, & L \ge 32
\end{cases}
$$

### 3.3 逆算（从总量 $T$ 求等级）

$$
L(T) = \begin{cases}
\sqrt{T+9} - 3, & 0 \le T \le 352 \\[4pt]
\dfrac{81}{10} + \sqrt{\dfrac{2}{5}\left(T - \dfrac{7839}{40}\right)}, & 353 \le T \le 1507 \\[4pt]
\dfrac{325}{18} + \sqrt{\dfrac{2}{9}\left(T - \dfrac{54215}{72}\right)}, & T \ge 1508
\end{cases}
$$

**为什么需要逆算**：经验条 UI 需要"当前等级内的进度"，存档只需存一个整数总量 $T$，
等级由逆算得出。这样**等级永远不会与总量不一致**。

（以上三式来源：<https://minecraft.wiki/w/Experience> §Leveling up，访问 2026-09-17。）

| 0 → 16 级 | **352 XP** | 同上 |

## 4. 掉落物实体

> `docs/research/01` §7「掉落物实体」已有：5 分钟消失、合并盒 0.5×0.25×0.5、
> 水中浮起、被水流/活塞推动、大堆保留原剩余时间。
> **本节只补它没写的：运动参数、拾取判定几何、销毁规则。**

### 4.1 运动参数（与玩家/生物不同！）

掉落物**有自己的一套重力与阻尼**，不要复用玩家物理参数
（来源：<https://minecraft.wiki/w/Entity> §Motion of entities，访问 2026-09-17）：

| 实体类别 | 执行序 | 重力 (格/tick²) | 阻尼（垂直） | 阻尼（水平） | 终端速度 (m/s) | 最大水平行程系数 |
|---|---|---|---|---|---|---|
| **玩家 / 生物 / 盔甲架** | 位置 → 加速 → 阻尼 | **−0.08** | 0.98 | **0.91**（着地时再乘方块摩擦） | 78.4 | 11.111 |
| **掉落物** | 加速 → 位置 → 阻尼 | **−0.04** | **0.98** | **0.98** | **39.2** | 50 |
| 经验球 | — | −0.03 | 0.98 | 0.98 | 29.4 | 50 |
| 下落方块 / TNT | 加速 → 位置 → 阻尼 | −0.04 | 0.98 | 0.98 | 39.2 | 50 |

**三处必须注意**：

1. **执行序不同**。玩家/生物是 **P → A → D**（先位移、后加速、最后阻尼）；
   掉落物是 **A → P → D**（先加速、后位移、最后阻尼）。顺序错了落点会偏。
   这与 `docs/03` §6 冻结的摩擦契约"阻尼施加在位移之后"是**同一个约束的两种表述** ——
   掉落物同样满足"阻尼在位移之后"，只是加速在位移之前。
2. **掉落物水平阻尼 0.98，不是 0.91**。这就是掉落物能在地上滑很远的原因。
3. **落地摩擦**：玩家/生物在 `OnGround` 时水平阻尼为 `0.91 × friction`；
   掉落物表**未标注**这一修正 —— 掉落物是否有同样的着地摩擦修正，wiki 未明说，
   **标"待校准"**（见 §7 R-4）。

> 弹跳：wiki 的 `Item (entity)` 页与 `Entity` 页**都没有给出掉落物的弹性系数（restitution）**。
> `docs/01` §5 写的"有重力与弹跳"中的**弹跳数值无可溯源来源** ——
> **标"待校准"，建议实现时先取 0（不弹跳）再做手感调整**（见 §7 R-5）。

### 4.2 拾取判定

- 掉落物碰撞盒：**0.25 × 0.25 × 0.25**（来源：<https://minecraft.wiki/w/Item_(entity)> 信息框，访问 2026-09-17）。
- 玩家"拾取盒" = 玩家碰撞盒**水平外扩 1 格、上下外扩 0.5 格**；
  水平方向**包含**边界（≤1），垂直方向**不包含**（<0.5）。
  拾取盒随玩家碰撞盒变化而变化（潜行/睡觉时变小）。
- 相交即可拾取；**多个掉落物可同时拾取**（与经验球的"逐个"相反）。
- 拾取延迟：自然生成/方块掉落 **10 tick（0.5 秒）**；**玩家投掷 40 tick（2 秒）**。
- 只装进主库存 27 + 快捷栏 9，**不进盔甲槽与副手**。装不下就留在地上。

（来源：<https://minecraft.wiki/w/Item_(entity)> §Behavior，访问 2026-09-17。）

### 4.3 合并规则（补充 `research/01`）

- 两个**同类型、可堆叠**的物品可合并，条件：合并后不超过该物品堆叠上限，
  且另一个在 **0.5×0.25×0.5** 的包围盒内。
- 合并后：**数量多的那个**保留并增加计数，另一个消失。
- 合并尝试周期：**每 40 tick**；**跨越方块边界时可每 2 tick** 处理一次；
  **传送后立即尝试合并**。
- 合并后计时器取**剩余时间更长**的那个。

（来源：<https://minecraft.wiki/w/Item_(entity)> §Merging / §Despawning，访问 2026-09-17。）

### 4.4 消失与销毁

| 情形 | 行为 | 来源 |
|---|---|---|
| 超时 | **6000 tick（5 分钟）**，仅在**已加载且处理实体的区块**内计时；区块卸载则**暂停** | <https://minecraft.wiki/w/Item_(entity)> §Despawning，访问 2026-09-17 |
| 落入虚空 | 低于 `世界最低建筑高度 − 64` 时**立即消失**（主世界 Y = −128） | 同上 |
| 环境伤害 | 掉落物**有 5 点生命**，被火/岩浆/仙人掌/爆炸摧毁；**不可被玩家或生物攻击** | 同上 §Damage |
| 下界之星 | 免疫爆炸 | 同上 |
| 岩浆/火免疫 | 下界合金类物品免疫火、浮在岩浆上 | 同上 |

> 注意：伤害**方块**如岩浆块、营火、甜浆果丛、凋零玫瑰、细雪**不伤害掉落物** ——
> 与 §1.4.2 寻路代价表里的"damage"不是同一套判据，别复用。

### 4.5 实现要点

1. 掉落物**不与其它实体碰撞**（船和潜影盒除外），只被方块阻挡。
2. 卡在实体方块内时，会**从无遮挡的侧面飞出**；若四周都是实体方块则**从顶部飞出**
   （即使下方是空的）。这解释了"往坑里填方块能把物品顶上来"。
3. 视觉：物品在世界中**不真的上下浮动/旋转**，那是渲染层效果；
   物理位置就是正弦动画的中心。旋转 1 rad/s，上下浮动 Y ∈ [0.0625, 0.2625]，周期 π 秒。

## 5. 食物与饱和度

### 5.1 为什么需要"饱和度"这个隐层（机制说明）

如果只有"饥饿"一个值，玩家吃任何食物后都会**立即开始掉饥饿**，
于是"吃饱"和"刚够"没有区别，食物的**质量**也无法表达。

基准设计是**两层**：

```
   行为产生耗竭 (exhaustion)
        │ 累计到 4.0 → 归零 → 扣 1 点
        ▼
   ┌─────────────┐
   │  饱和度层    │  ← 先扣这里（隐层，不显示）
   │  (saturation)│     上限 = 当前饥饿值
   └──────┬──────┘
          │ 为 0 时
          ▼
   ┌─────────────┐
   │  饥饿层      │  ← 再扣这里（显示为鸡腿）
   │  (hunger)    │     上限 20
   └─────────────┘
```

**三条设计后果**（这才是"为什么需要它"）：

1. **食物质量可表达**：优质食物给高饱和度（金胡萝卜 6 饥饿 / **14.4** 饱和），
   劣质食物给低饱和度（腐肉 4 饥饿 / **0.8** 饱和）。
   同样填饱 4 点饥饿，前者能撑很久，后者立刻又开始掉饥饿。
2. **回血速度可表达**（见 §5.3 的饱和度增益）—— 高饱和食物回血飞快。
3. **"刚好不饿"和"吃撑了"有区别**：饱和度上限 = 当前饥饿值，
   所以饥饿低时吃再多也存不下多少饱和度。

（机制来源：<https://minecraft.wiki/w/Food> §Hunger / §Saturation / §Exhaustion，访问 2026-09-17。）
