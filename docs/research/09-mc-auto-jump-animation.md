## 摘要与问题陈述

在 3D 游戏角色控制器（Kinematic Character Controller）设计中，运动的物理有效性（Physics Validity）与视觉连贯性（Visual Coherence）通常由动画状态机进行桥接。Minecraft 的“自动跳跃（Auto-Jump）”机制自引入以来，在人机交互与视觉体验层面引发了持久的争议。

该机制的核心矛盾在于：**底层的离散冲量注入逻辑，与上层基于光流连续性的视网膜感知之间存在显著失谐。**

本白皮书将聚焦于自动跳跃的**动画呈现链路（Visual Presentation Pipeline）**，解构其在第一人称视锥矩阵、第三人称程序化骨骼驱动、物理帧插值以及前庭-视觉人机工效学上的深层表现。

## 1. 渲染架构与时间轴解耦（Temporal Decoupling & Pipeline Architecture）

Minecraft 采用经典的双时钟解耦架构：逻辑层运行于固定的 20 Hz（50ms/tick）物理时钟，渲染层则运行于可变的非同步垂直同步/高帧率时钟（Variable Render Framerate）。这一机制决定了自动跳跃动画必须由插值（Interpolation）系统动态合成。

```
[ 物理层: 20 Hz (50ms) ]   Tick N (起跳触发: Vy = 0.42)           Tick N+1 (衰减: Vy = 0.333)
                                 │                                      │
                                 ▼                                      ▼
[ 插值层: LERP α ∈ [0,1) ]      ├─── α=0.2 ───┼─── α=0.5 ───┼─── α=0.8 ───┤
                                 │             │             │             │
[ 渲染层: >60 Hz 变帧率 ]        ▼             ▼             ▼             ▼
                               Frame 1       Frame 2       Frame 3       Frame 4
                         (变换栈更新)   (视角矩阵变换) (光栅化光流)  (模型关节重绘)
```

### 1.1 亚帧线性插值数学表述（Partial Tick LERP）

为了使 20 Hz 的离散跳跃在 144 Hz 以上的高刷显示器中不呈现阶梯状抽搐，客户端引擎在渲染阶段使用归一化的时间余量 $\alpha \in [0.0, 1.0)$ 进行线性插值：

$$\mathbf{P}_{render} = \mathbf{P}_{prev} + (\mathbf{P}_{curr} - \mathbf{P}_{prev}) \cdot \alpha$$

$$\alpha = \frac{T_{render} - T_{tick\_start}}{\Delta T_{tick}}$$

在自动跳跃触发的瞬时帧：

- **Tick $N$：** 玩家检测到前方完整方块障碍，跳跃输入置为真，垂直速度突变注入 $v_y^{(N)} = 0.42 \text{ m/tick}$。

- **Tick $N-1 \to N$ 渲染阶段：** 上一帧垂直速度可能为 $0.0$ 或极小（微重力贴地），两帧之间的位移差产生极大的一阶导数突变（Jerk），插值器直接忠实还原该突变，使相机坐标在瞬间进入一条高斜率抛物线。

### 1.2 变换矩阵栈（渲染变换栈）

相机与实体骨骼在每渲染帧经历严格的矩阵层叠计算：

$$\mathbf{M}_{final} = \mathbf{M}_{Projection} \times \mathbf{M}_{Camera} \times \mathbf{M}_{Bobbing} \times \mathbf{M}_{EntityTranslation} \times \mathbf{M}_{BoneRotation}$$

自动跳跃不仅重构了 $\mathbf{M}_{EntityTranslation}$，还会瞬间覆写 $\mathbf{M}_{Bobbing}$ 和 $\mathbf{M}_{BoneRotation}$ 的输入状态机。

## 2. 第一人称视角呈现与光流扰动（First-Person View Dynamics）

第一人称视角是自动跳跃视觉争议的重灾区。玩家未进行输入操作，视角却剧烈晃动，其本质源于视锥变换管线中的三组复合效应。

### 2.1 视界晃动（View Bobbing）的相位截断与下压

原版的平地行走晃动依赖累积位移参数 `walkDist`。其视角旋转矩阵偏移（Roll/Pitch）由三角函数计算：

$$\text{Pitch}_{bob} = A \cdot \vert{}\cos(\omega \cdot \text{walkDist})\vert{}$$

$$\text{Roll}_{bob} = B \cdot \sin(\omega \cdot \text{walkDist})$$

```
                   行走摇晃 (平滑三角波)               自动跳跃截断点
Pitch Offset  ▲                                             │
              │         /\                  /\              │   垂直视角强制平移
              │        /  \                /  \             │   ▲
       0.0    ┼───────/────\──────────────/────\────────────┼───┼───────────► Time
              │      /      \            /      \           │  /
              ▼     /        \          /        \          ▼ / (抛物线抬升)
                                                       (相位突断)
```

- **相位打断：** 当自动跳跃触发导致 `onGround = false` 时，系统判定离开地面，步行动画被强制切断并迅速阻尼衰减至归零。

- **动量叠加：** 视角尚未完成上一个周期自然的“下落摆动”，便直接叠加了绝对坐标的急速抬升。原本平滑的周期性视觉波动被锐利的垂直脉冲强行打断，形成视觉上的“顿挫卡顿感（Visual Hitch）”。

### 2.2 垂直视差与光流矢量突变（Optical Flow Jerk）

人类视觉系统通过视网膜图像上像素运动的矢量场（光流，Optical Flow）来推断自身的空间运动。

| **运动类型**                  | **水平光流速度 ux​** | **垂直光流速度 uy​**     | **光流加速度导数（Jerk）** | **人体前庭感知预期**     |
| ------------------------- | -------------- | ------------------ | ----------------- | ---------------- |
| **平地滑行（Step-Height 0.6）** | 恒定             | 微小台阶微扰             | 极低，呈连续平滑过渡        | 完全吻合前向视觉流        |
| **手动预判起跳（Manual Jump）**   | 微增（疾跑）         | 连续二次抛物线            | 高，但存在神经前馈抑制       | 大脑提前准备，无眩晕感      |
| **自动跳跃（Auto-Jump 1.0）**   | 保持或因撞墙突降       | 脉冲式起飞 ($v_y=0.42$) | 极高，非预期的阶跃冲击       | **前馈缺失，引发视网膜滑移** |

由于自动跳跃算法在极低台阶（如 $0.6 \sim 0.8$ 格的高低差）与标准方块（$1.0$ 格）中施加完全相同的跳跃动量，导致玩家即便只是掠过一截小坑洼，视角也会被突兀地向上抛起 $1.25$ 格，视野中心点剧烈震荡。

### 2.3 动态视场角畸变（Dynamic FOV Distortion）

在玩家疾跑（Sprinting）触发自动跳跃时，渲染引擎会同时计算疾跑带来的 FOV 放大系数（约 $+15\%$）以及着地/浮空的动态插值。如果跳跃中途因碰撞导致疾跑状态瞬时丢失（如微小的侧向蹭墙），FOV 会在瞬间发生骤缩与回弹，引发镜头呼吸效应（Breathing Glitch）。

## 3. 第三人称模型骨骼与程序化动画动力学（Third-Person Skeletal Dynamics）

Minecraft 不包含预烘焙（Baked）的骨骼动画剪辑（Clip），所有实体的外形动画均由客户端每帧通过数学公式实时计算，即**全程序化骨骼旋转（Procedural Bone Animation）**。

```
                       [ 实体根节点: Root ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   [ 躯干: Body ]         [ 左臂 / 右臂 ]         [ 左腿 / 右腿 ]
 (Pitch微前倾: 0~0.1rad) (浮空伸展 / 锁定抑制) (相位差倒置 / 腾空悬停)
```

### 3.1 肢体摆动变量衰减模型（Limb Swing Mechanics）

实体的四肢旋转依赖两个核心运行时变量：

- `limbSwing`：类似里程计的累积行进距离（弧度输入）。

- `limbSwingAmount`：肢体摆动的振幅插值（速度响应标量）。

在自动跳跃触发后：

$$\text{limbSwingAmount} \leftarrow \text{limbSwingAmount} \times 0.4 \quad (\text{逐 Tick 空中衰减})$$

腿部与手臂的旋转角方程由双足简谐振动变更为悬空固定姿态：

$$\theta_{leg\_left} = \cos(\text{limbSwing} \cdot 0.6662) \times 1.4 \times \text{limbSwingAmount}$$

$$\theta_{leg\_right} = \cos(\text{limbSwing} \cdot 0.6662 + \pi) \times 1.4 \times \text{limbSwingAmount}$$

当玩家自动起跳时，原本剧烈前后摆动的双腿由于 `limbSwingAmount` 的急剧衰减，在约 $2 \sim 3$ 个 Tick 内迅速收拢并凝固为一个微幅后张的悬空姿态。

### 3.2 姿态阶段状态机（Jump Pose States）

```
[ 地面奔跑态 ]
   │
   ├─► 【起跳预备 (Anticipation)】: 缺失（0帧下蹲预备，瞬间起飞）
   │
   ├─► 【上升加速期 (Ascent)】: 躯干无形变，双腿程序化向后轻微展开
   │
   ├─► 【最高抛物顶点 (Apex)】: 悬空帧滞留约 1~2 个 Tick，四肢几乎静态冻结
   │
   ├─► 【自由下落期 (Descent)】: 保持与上升期完全对称的刚性姿态
   │
   └─► 【触地挤压 (Impact Squat)】: 缺失（无反向运动学 IK 支撑，直接切换为地面步行摆动）
```

这种呈现呈现出强烈的“玩具木偶刚体感”：

1. **起跳缺乏预备动作（Zero Anticipation）：** 传统动画原则中的“Squash and Stretch”（挤压与伸展）完全缺失。在水平行进中没有任何下蹲蓄力帧，角色直接转入垂直加速。

2. **缺乏反向动力学（No Inverse Kinematics - IK）：** 当角色跳上台阶表面瞬间，脚部碰撞体直接与方块顶面重叠，系统通过瞬时刚性平移将玩家置于台阶上方，缺乏脚踝踩地屈膝的吸收动画。

## 4. 人机工效学与知觉心理学分析（Visual Perception & Ergonomics）

自动跳跃在玩家感知上造成的负面体验，在人机交互领域有坚实的认知神经学解释。

```
【主动手动跳跃 (Manual Jump)】
玩家意图 ──► [中枢运动前馈指令] ──┬─► 手指敲击空格 (按键触感)
                                   └─► 视皮层预先抑制 (消除眩晕)
                                               │
                                   [视觉抛物线光流发生] ◄── 完全符合知觉预期

【被动自动跳跃 (Auto-Jump)】
环境阻挡 ──► [客户端算法自主触发] ────► 突发物理冲量与光流位移
                                               │
                                   [大脑前庭系统未收到预警]
                                               │
                                   ▼ 视觉与前庭感觉产生冲突
                                   【前庭-眼动反射失调 / 3D眩晕】
```

### 4.1 前馈控制缺失与视网膜滑移（Retinal Slip）

人类在主动操控角色起跳时，大脑会发出“传出神经副受冲动（Efference Copy）”，提前在视觉中枢压制由于急速视角变动产生的运动模糊与位移不适。然而，自动跳跃是由黑盒判定驱动的：

- 玩家注意力往往聚焦于准星正中央的准星或远方景物。

- 客户端感知到底部 1 格台阶并触发跳跃时，玩家大脑并未下达起跳指令。

- 视野突变引发视网膜像面的剧烈非自愿滑移，导致玩家产生失控感与动晕症（Simulation Sickness）。

### 4.2 视觉高宽比错觉（Aspect Ratio Discrepancy）

方块世界的网格是严格的 $1.0 \times 1.0 \times 1.0 \text{ m}$ 正方体。当玩家以平滑视角逼近立方体垂直面时，视角在离方块边缘仅约 $0.2 \sim 0.5$ 格距离内突然抬升，造成极大的近截面视差放大效应（Parallax Explosion），贴图在视界边缘以极高的角速度被拉伸划过。

## 5. 工业级动画平滑方案与技术重构建议

针对 Minecraft 自动跳跃生硬的呈现问题，现代游戏引擎通常采用以下三种技术手段进行视觉修正与渲染缓冲：

```
                ┌───────────────────────────────────┐
                │ 物理碰撞代理层 (Physics Collider) │ 保持原生 AABB 刚性跳跃
                └─────────────────┬─────────────────┘
                                  │
                   解耦隔离 (Decoupling Separation)
                                  │
                                  ▼
                ┌───────────────────────────────────┐
                │  渲染视图代理层 (Render Proxy)   │
                └─────────────────┬─────────────────┘
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼                                                 ▼
【临界阻尼弹簧平滑 (Spring-Damper)】             【自适应初速度调制 (Adaptive Impulse)】
 过滤垂直跳跃脉冲，生成 S 曲线过渡              根据障碍净高度动态调整抛物线振幅
```

### 5.1 摄像机弹簧阻尼解耦架构（Decoupled Spring-Damper System）

彻底解耦相机的局部垂直坐标与物理碰撞盒的绝对位移。碰撞体严格执行半隐式欧拉积分跳跃，而相机则作为附着在碰撞盒上的一个二阶阻尼系统（Critically Damped Spring）：

$$\ddot{y}_{cam} + 2\zeta\omega_n \dot{y}_{cam} + \omega_n^2 (y_{cam} - y_{physics}) = 0$$

- 阻尼比设为临界阻尼 $\zeta = 1.0$，消除震荡。

- 在触发自动跳跃时，刚性跃升的折线经过二阶低通滤波后，在第一人称相机中表现为一条连续平滑的 Sigmoidal（S型）过渡曲线，彻底过滤掉高频视觉抖动（Jitter）。

### 5.2 视差自适应冲量调制（Adaptive Visual Impulse）

改变“只要遇到阻挡就恒定施加 0.42 冲量”的粗暴逻辑。根据前向射线与障碍物求交得到的精确垂直高度差 $\Delta h = H_{obs} - Y_0$，自适应映射起跳垂直动力与相机动画振幅：

$$v_y^{(init)} = \sqrt{2 \cdot g_{eff} \cdot (\Delta h + \epsilon)}$$

针对 $0.6$ 格的半砖或破碎地形，施加仅能越过对应高度的极低抛物线动画，大幅压缩第一人称垂直光流的角位移。

### 5.3 虚拟足底反向动力学（Procedural Foot IK）

在第三人称动画管线中，引入两段式足底逆向运动学（Two-Bone IK）：

- 在射线检测到脚底即将踏上台阶表面前 $100 \text{ ms}$，程序化触发腿部骨骼向上弯曲缩起（Tuck Legs）。

- 接触台阶瞬间，利用腿部伸展动画吸收垂直位移冲击，使得上半身与摄像机高度在此期间几乎保持等高水平匀速推进，实现类似“跨栏迈步”而非“整个人直立弹射”的自然视觉表现。
