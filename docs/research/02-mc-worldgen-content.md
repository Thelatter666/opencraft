## 1. 世界结构基础

### 1.1 坐标与 Y 层范围（1.18+）

| 项目 | 数值 | 说明 |
|---|---|---|
| 主世界 Y 范围 | **-64 ~ 319**（共 384 格） | 1.18 起从旧的 0~255 扩展 |
| 基线 Y=0 | 深板岩起始过渡层 | Y=0→Y=8 渐变，深板岩矿石只在 Y<8 出现 |
| 基岩层（JE） | Y=-64 为全基岩，向上至约 Y=-59 渐变稀疏 | 由 surface rule 中的 bedrock 层实现 |
| 下界 Y 范围 | **0 ~ 127**（共 128 格） | 1:8 坐标比维度 |
| 末地 Y 范围 | 0~255（生成算法基于旧高度上限） | 中央岛地面约 Y=64 |

- 方块坐标为整数格点；实体坐标为浮点。区块内方块按 (x, y, z) 存储，Anvil 格式 1.2.1 起采用 **YZX 排序**以改善压缩率（同类型方块相邻）——这是"数据布局为压缩服务"的设计动机，OpenCraft 可借鉴。
- 温度随高度衰减：Y≥81 后每上升 1 格温度降低 **0.00125 (1/800)**，这决定了雪山山顶的积雪/降雪行为。

### 1.2 区块（Chunk）

- **16 × 384 × 16** 方块/区块（主世界）；内部按 16³ 的 section 分割，主世界共 **24 个 section**。
- 区块是生成、保存、加载、随机刻的基本单位。
- 区块状态机（1.18+ 生成流水线，12 个阶段）：
  `empty → structures_starts → structures_references → biomes → noise → surface → carvers → features → initialize_light → light → spawn → full`
  - 早期阶段产物为 **proto-chunk（原型区块）**，完成后成为 **level chunk**。
  - `biomes` 阶段先于地形：先用 6 维参数确定每格生物群系，再用地形噪声塑形——群系与地形解耦是 1.18 的核心设计。
- 地物（features）装饰分 11 个子步骤（GenerationStep.Decoration）：
  `raw_generation → lakes → local_modifications → underground_structures → surface_structures → strongholds(未使用) → underground_ores → underground_decoration → fluid_springs → vegetal_decoration → top_layer_modification`

### 1.3 加载区 / 渲染区（视距）

- **视距（view/render distance）**：客户端可设置 3~32 区块（默认约 12），以玩家为中心渲染方形/圆形范围。
- **模拟距离（simulation distance）**：1.18+ 独立于视距，控制实体运算、随机刻、作物生长等"完全模拟"范围（默认 10）。
- 加载采用**票券（ticket）层级**机制：不同来源（玩家、出生点、传送门、地图）发放不同等级票券，等级决定该区块是"实体运算（entity-ticking）"还是"仅方块运算（ticking）"还是"仅加载不运行"。OpenCraft 可实现简化版两级：渲染加载 + 逻辑模拟。
- **出生区块（Spawn chunks）**：历史上是世界出生点周围始终加载的区块（Java），1.21.9 起被移除/改版；新世界出生点由游戏在 **出生点周围 5 区块半径内逐块检查**选取安全地面（World spawn 条目）。

### 1.4 世界边界

- 默认位于 **X/Z = ±29,999,984**；可通过命令扩大至最大 **±59,999,968**。
- 越界玩家持续受伤（默认伤害随边界外距离增加）；边界外方块不可交互。
- 边界是"软边界"：世界数据仍可存在，但游戏限制可达范围。OpenCraft 采用同样软边界策略最省事。

### 1.5 种子机制（Seed）

- 种子为 **64 位有符号整数**，范围 **−2⁶³ ~ 2⁶³−1**，总空间 2⁶⁴ ≈ 1.84×10¹⁹ 个世界。
- 字符串种子（含非数字字符）走 Java `String.hashCode()`，仅能命中 **2³²** 个世界——OpenCraft 可用任意自己的哈希（如 FNV-1a/xxHash），不需要兼容。
- **同一种子 + 同一版本 = 相同世界**；算法更新（如加新群系）后同种子不再产出相同地形。
- Java 1.18 快照期间曾出现 48 位种子限制 bug（MC-236650），21w41a 更换 PRNG 后恢复 64 位；Overworld 生成使用 **xoroshiro128++** 系 PRNG + Perlin 梯度噪声（多倍频叠加）。
- 工程要点（对 OpenCraft 有用）：种子会派生出多路子流（地形、群系、结构、特征各用独立流），避免"改一处全盘变动"。MC 的做法是为不同子系统用世界种子加常数偏移派生子种子（ wiki 未在单页明确给出偏移表，但从结构集 salt 机制可见其意图，见 §2.6）。

## 2. 地形生成流水线（1.18+ Overworld）

### 2.1 总览

1. **结构起始点**（structures_starts）——先决定哪些区块是结构起点（见 §2.6）。
2. **生物群系**（biomes）——6 参数气候系统（见 §2.2）。
3. **基础地形**（noise）——3D 密度函数 + 液体（海平面 Y=63）。
4. **地表规则**（surface）——按群系替换表层方块（见 §2.4）。
5. **雕刻**（carvers）——洞穴/峡谷（见 §2.5）。
6. **地物与结构部件**（features）——矿石、植被、结构区块（见 §2.6/§2.7）。
7. 光照 → 出生点 → 完成。

### 2.2 生物群系放置：六参数气候系统

主世界生物群系由 6 维参数空间的区间查表决定（5 个来自水平坐标噪声，depth 来自地形）：

| 参数 | 作用 | 分级（区间值） |
|---|---|---|
| 温度 Temperature | 热带↔寒带群系 | 5 级：-1.0~-0.45 / -0.45~-0.15 / -0.15~0.2 / 0.2~0.55 / 0.55~1.0 |
| 湿度 Humidity | 沙漠↔雨林 | 5 级：-1.0~-0.35 / -0.35~-0.1 / -0.1~0.1 / 0.1~0.3 / 0.3~1.0 |
| 大陆性 Continentalness | 海洋↔内陆 | 蘑菇岛 -1.2~-1.05；深海 -1.05~-0.455；海洋 -0.455~-0.19；海岸 -0.19~-0.11；近内陆 -0.11~0.03；中内陆 0.03~0.3；远内陆 0.3~1.0 |
| 侵蚀 Erosion | 高侵蚀=平坦低地，低侵蚀=山地 | 7 级：E0 -1.0~-0.78 … E6 0.55~1.0 |
| 怪异性 Weirdness | 群系变体（丛林→竹林等）与破碎地形 | 由其导出 PV 值 |
| 深度 Depth | 地表 vs 洞穴群系 | ≈地表 0，每下探 1 格 +1/128（0.0078125） |

- **PV（Peaks & Valleys）公式**：`PV = 1 − |3·|weirdness| − 2|`，五档：
  Valleys -1.0~-0.85 / Low -0.85~-0.2 / Mid -0.2~0.2 / High 0.2~0.7 / Peaks 0.7~1.0。
- 洞穴群系由 depth 组合触发：
  - 钟乳石洞：depth 0.2~0.9 且大陆性 0.8~1.0
  - 繁茂洞穴：depth 0.2~0.9 且湿度 0.7~1.0（与钟乳石洞重叠，见 MC-262252）
  - 深暗之域：depth≈1.1 且侵蚀 -1.0~-0.375
- 每个群系还有自身属性：基础温度（沙漠/恶地 2.0、丛林 0.95、平原 0.8、森林 0.7、沼泽 0.9、雪原 0.0、雪坡 -0.3、尖峭山峰 -0.7）与 downfall 湿度（0.0~1.0，主要用于叶/草颜色）。
- 未落在任何群系区间时，取**最近**的群系区间——这是实现"无缝群系过渡"的关键技巧，OpenCraft 建议照此设计。

### 2.3 密度函数（Density Function）概念

- 3D Perlin 噪声对每个方块输出**密度值**：>0 实心、<0 空气，天然支持悬空结构与任意 3D 地形。
- 密度叠加**高度偏置（height bias / squash）** 与**基准高度（base height）**：偏置把地形"垂直压缩"向目标表面，基准高度整体抬升/下压。
- 各维度复用同一思想：
  - 主世界：单组偏置/基准（放大化世界=调低偏置实现垂直拉伸）。
  - 下界：两组基准 → 顶部/底部实心壳 + 中间空腔。
  - 末地：参数压缩成底部大岛。
- 额外子系统：
  - **含水层（Aquifers）**：决定洞穴内局部液面（空气/水/熔岩），Y=-55 以下恒为熔岩；深暗之域区域恒为空气。
  - **矿脉（Ore Veins）**：仅主世界，三个噪声（toggle 决定铜/铁、ridge、gap 决定矿比 10%~30%），Y=-60~51 之外关闭，98% 矿石 + 2% 粗金属块。

### 2.4 地表规则（Surface Rules）

数据驱动的"按条件替换表层方块"规则链，要点（JE）：

- 基岩：Y=-64 全基岩 → Y=-59 渐变消失。
- 深板岩：Y=0 以下，Y=0→Y=8 渐变过渡到石头。
- 恶地：Y≥256 橙陶瓦；Y≥74 噪声陶瓦；其余为硬编码彩色陶瓦条带（banded）。
- 冰封山峰：陡面/噪声→浮冰，冰噪声 0~0.025 → 冰。
- 石峰：方解石噪声 -0.0125~0.0125 → 方解石，否则石头。
- 红树林沼泽 → 泥巴；蘑菇岛 → 菌丝体；末地 → 恒为末地石。
- OpenCraft 建议：实现为"按群系的条件规则列表（深度/噪声/陡度谓词）"，而非硬编码每个群系。

### 2.5 洞穴生成

三类**噪声洞穴**（由频率、空洞度、厚度三张噪声图控制）+ 传统 carver：

| 类型 | 特征 |
|---|---|
| 芝士洞（Cheese） | 大型口袋空洞，空洞度控制大小，常形成大厅 |
| 意面洞（Spaghetti） | 长窄蜿蜒隧道，厚度控制 |
| 面条洞（Noodle） | 意面洞的更细变体，隧道宽 1~5 格 |

另有：峡谷 carver、溶洞（Dripstone Caves 群系）、繁茂洞穴、深暗之域（幽匿结构）。含水层负责洞穴中的水/熔岩分布（§2.3）。

### 2.6 矿石分布（1.18+，主世界）

| 矿石 | Y 范围 | 峰值层 | 备注 |
|---|---|---|---|
| 煤 Coal | 0 ~ 320 | **45** | 不含化石；-64~-1 无 |
| 铜 Copper | -16 ~ 112 | **43** | 溶洞中矿脉更大 |
| 青金石 Lapis | -64 ~ 64 | **-2** | |
| 铁 Iron | -64~72 及 80~320 | **14** | 73~79 为无生成带；较稀有 |
| 金 Gold | -64 ~ 32 | **-18** | 恶地额外 -16~320，峰值 32~256 |
| 红石 Redstone | -64 ~ 256（实际集中深部） | **-59** | 稀有 |
| 钻石 Diamond | -64 ~ 16 | **-59** | 深部最富 |
| 绿宝石 Emerald | -64 ~ 320（山地群系） | ~85 | 散布单块（不成矿脉），仅山地/风袭类群系，非常稀有 |

下界矿石：下界石英峰值 Y=114（Y≥128 无）；下界金峰值 Y=16；**远古残骸峰值 Y=16**，向上向下快速衰减（Y≥120 无）。
详细矿脉大小/尝试次数在 wiki 的 Ore feature 子页（本次未展开，需时可查）。

### 2.7 结构生成

**放置算法（spacing/separation 网格）**：世界被划成 spacing×spacing 区块的大格，每格内按 salt 种子随机选一个位于"内缩 separation"范围的区块作为结构起点。数值来自原版数据包 `worldgen/structure_set`（1.18+）：

| 结构 | spacing | separation | 群系限制举例 |
|---|---|---|---|
| 村庄 | 34 | 8 | 5 变体：平原/沙漠/热带草原/针叶林/雪原 |
| 林地府邸 | 80 | 20 | 黑森林、苍白之园 |
| 海底神殿 | 32 | 5 | 深海 |
| 远古城市 | 24 | 8 | 仅深暗之域 |
| 掠夺者前哨站 | 32 | 8 | 多种地表群系（不得在村庄点位 10 区块内） |
| 试炼密室 (1.21) | 34 | 12 | 除深暗之域外全部群系 |
| 沙漠神殿/丛林神庙/雪屋/沼泽小屋 | 32 | 8 | 各自群系 |
| 沉船 | 24 | 4 | 海洋/海滩 |
| 海底废墟 | 20 | 8 | 海洋 |
| 下界要塞 | 27 | 4 | 下界全部群系 |
| 堡垒遗迹 | 27 | 4 | 下界（不在玄武岩三角洲） |
| 末地城 | 20 | 11 | 末地外岛 |

- **要塞（Stronghold）是特例**：不用 spacing/separation，而是**同心环**放置——Java 版共 **128 个，8 环**（1.9/15w43a 起）：
  环1: 3 个 @1280–2816 格 / 环2: 6 @4352–5888 / 环3: 10 @7424–8960 / 环4: 15 @10496–12032 / 环5: 21 @13568–15104 / 环6: 28 @16640–18176 / 环7: 36 @19712–21248 / 环8: 9 @22784–24320（最外环实际为异常的 36° 间隔）。
  - 每座要塞含 **12 个末地传送门框架**，每个框架 **10% 概率**预置末影之眼（期望 1.2 颗）；全部预填概率 10⁻¹²。
  - 房间：起始螺旋楼梯 → 五岔路口；图书馆 0–2 个（大型 233 书架/小型 161）；监狱大厅 0–5；祭坛走廊 0–4 等；整座结构可延伸至距起点 50 房间/水平半径 112 格。
- **废弃矿井**与**埋藏的宝藏**用每区块概率而非网格（埋藏宝藏约 1%/区块）。
- **结构定位方式**：末影之眼（要塞）、海洋/林地/试炼探险家地图（神殿/府邸/密室）、海豚带路（沉船/废墟）、藏宝图（埋藏的宝藏）、`/locate` 指令（1.11 加入）。
- 结构生成可**溢出**到相邻已生成区块；特征溢出导致同种子世界因探索顺序不同有细微差异（MC-55596）——OpenCraft 若追求确定性，应在区块边界处理上明确截断或引入"边界补生成"。

## 3. 生物群系清单

**Java Edition 共 66 个群系类型：主世界 55 个、下界 5 个、末地 5 个**，另有 1 个仅用于超平坦预设的虚空（the_void）。（Biome 条目，1.21.x 前后口径）

### 3.1 主世界（55 个，按类别归类）

- **温带**：平原、向日葵平原、森林、桦木森林、原始桦木森林、黑森林、樱花树林(1.20)、繁花森林
- **针叶/寒带**：针叶林、原始松木针叶林、原始云杉针叶林、积雪针叶林、雪原、冰刺之地、积雪沙滩、冰封河、冻洋、深冻洋
- **热带**：丛林、竹林、稀疏丛林、热带草原、热带高原、风袭热带草原
- **干旱**：沙漠、恶地、风蚀丘陵（windswept hills/gravely hills）
- **湿润/水生**：沼泽、红树林沼泽、海滩、石岸、海洋、深海、温水海洋、冷水海洋、冻结海洋、暖水海洋、深海变体 4 种
- **洞穴**：溶洞、繁茂洞穴、深暗之域
- **山地**：草甸、樱花树冠外的高地（Grove 雪林）、雪坡、尖峭山峰、冰封山峰、裸岩山峰、湍急河流、冻结峰顶等
- **特殊**：蘑菇岛（孤立于深海旁）、蘑菇岛岸、河流、河岸类
- 群系差异体现为：**地表方块**（surface rule 决定，如恶地陶瓦、红树林泥巴、蘑菇岛菌丝）、**生物生成表**（被动/敌对生物权重）、**下雪阈值**（基础温度 <0.15 任意高度下雪，如冻河/雪原/冰刺）、**结构种类**（村庄 5 变体按群系选择）、**树木/植被装饰**。

### 3.2 下界（5 个，1.16 Nether Update 引入 3 个）

| 群系 | 生成占比 |
|---|---|
| 下界荒地 (Nether Wastes) | 36.30% |
| 绯红森林 (Crimson Forest) | 22.22% |
| 灵魂沙峡谷 (Soul Sand Valley) | 17.08% |
| 玄武岩三角洲 (Basalt Deltas) | 15.86% |
| 诡异森林 (Warped Forest) | 8.54% |

- 群系决定：地表方块（下界岩/灵魂沙/玄武岩/黑石）、生物（绯红=猪灵+疣猪兽；诡异=末影人为主；灵魂峡谷=恶魂+骷髅）、结构（要塞全域；堡垒遗迹不在玄武岩三角洲；下界化石仅灵魂沙峡谷，14 种造型）。

### 3.3 末地（5 个，JE 专属；BE 合并为 1 个）

- the_end（中央岛）、Small End Islands、End Midlands、End Highlands、End Barrens——按距中心岛的径向距离/噪声划分，End Highlands 生成末地城。

## 4. 三个维度

### 4.1 主世界（Overworld）

- 上述全部流水线的载体；海平面 **Y=63**；出生点在 (0,0) 附近安全地面随机选取（gamerule `spawn_radius` 默认 10 区块半径内随机）。

### 4.2 下界（The Nether）

| 规则 | 数值 |
|---|---|
| 坐标比 | **1:8**（下界 1 格 = 主世界 8 格），跨维度传送坐标 ÷8 / ×8 |
| 总高度 | 128 格（Y=0~127） |
| 底部基岩 | Y=0~4 |
| 顶部基岩屋顶 | Y=123~127（约 5 层）——防止从"天空"进入；可站屋顶 |
| 熔岩海 | Y=31 及以下 |
| 时间 | 无昼夜、无天气；主世界时间冻结 |
| 床 | 爆炸（威力 5，强于 TNT 的 4） |
| 流体 | 熔岩流速 3 倍、流淌 8 格 |
| 指南针/钟 | 乱转（除非绑磁石/校准） |

- 传送门：黑曜石框最小 **4×5**、最大 **23×23**；生存点火后站立 4 秒传送；无对应门时在对侧自动生成 4×5 门。传送门是"降低长距离旅行成本"的核心设计，OpenCraft 应保留 1:8 比例带来的策略性。
- 结构：下界要塞（烈焰人/凋灵骷髅，烈焰人刷怪笼）、堡垒遗迹（20w16a）、下界化石、废弃传送门（主世界也有，7 种变体）。

### 4.3 末地（The End）

- **中央岛**：末地石构成；进入末地固定传送到 **(100, 49, 0)** 的 5×5 黑曜石平台（每次进入都重建）；出口传送门位于 (0,64,0)。
- **黑曜石柱**：**10 根**围成半径 **42 格**的环，柱体贯穿至 Y=0；柱顶末影水晶（2 个有铁笼）为龙回血。
- **末影龙**：首杀经验 **12,000**，此后 500/条；可用 4 个末影水晶复活；**仅前 20 条龙**每条生成一个末地折跃门。
- **末地折跃门（Gateway）**：1 格高入口，通常投掷末影珍珠进入；连接主岛与外岛。
- **外岛**：与主岛间隔约 **1000 格**虚空；以同心环状生成（受算术溢出 bug 影响，JE 至 26.3 前）：第一环止于 ±370,720 格，第二环 ±524,288~642,112，第三环起于 ±741,455，玩家最多可达第 **6,548** 环；生成条件为 `sin(X²+Z²/43748131634) > 0` 且 `X²+Z²−1,000,000 > 0`。
- 末地城/末地船：鞘翅唯一来源；紫颂树。环境：无昼夜无天气，天空周期性紫闪（30 秒间隔、持续 5–19 秒）；床/重生锚爆炸威力为 TNT 的 125%；末影之眼不可投掷。

## 5. 时间与周期

### 5.1 昼夜循环

- 一天 = **24,000 ticks = 20 分钟现实时间**（现实:游戏 = 72:1）；1 Minecraft 小时 = 1000 ticks = 50 秒。
- 关键时点：0 = 06:00 日出后；6,000 = 正午；12,000 = 日落开始（黄昏 50 秒）；13,000 = 夜晚；18,000 = 午夜；23,000 = 日出开始。
- 白天 10 分钟、夜晚 8 分 20 秒；晴天可睡床的窗口为 12,542~23,460 ticks。
- `/time set` 上限 2³¹−1 ticks ≈ 89,478 游戏日。

### 5.2 月相

- **8 个月相**，每晚推进 1 个（满月→凸月→半月→娥眉月→新月→再回到满月），周期 8 游戏日（192,000 ticks ≈ 2.6 小时现实）。
- 月相影响：区域难度（见 §7.2）、骷髅陷阱马概率、满月时猫/史莱姆生成倾向。月相值 0~7，满月=0。

### 5.3 天气

- 内部为 rain/thunder 两个布尔标志 + 随机计时器：
  - rain 开启 12,000–24,000 ticks（10–20 分钟），关闭 12,000–180,000 ticks（10 分钟~2.5 小时）
  - thunder 开启 3,600–15,600 ticks（3–13 分钟），只在 rain 开启时生效
- 雨只在温度 >0.15 的群系下（沙漠/热带草原/恶地不下）；温度 <0.15 为雪；雪与雨在引擎内是同一天气状态。
- 雷暴中午天光内部值 10，但怪物生成系统视天光为 0（可全天刷怪）；闪电可点燃方块、把苦力怕变高压苦力怕、村民变女巫、猪变僵尸猪灵、哞菇变棕色哞菇；普通难度闪电伤害 5 点。
- 雨的其他效果：钓鱼等待更短、耕地湿润、炼药锅积水、熄灭火焰（不下界岩上的火）、潮涌力量激活。
- 睡觉跳夜时会同时把天气清为晴天。

### 5.4 床与重生锚

- **床**：主世界睡眠设置重生点并跳过夜晚（多人需 `playersSleepingPercentage` 默认 100% 的玩家入睡）；在下界/末地使用会**爆炸**（威力 5，TNT 的 125% 按 End 条目口径）。
- **重生锚**（1.16）：用荧石充能至多 **4 格**，在**下界**设置重生点并消耗 1 格充能；在主世界/末地使用会爆炸。设计动机：给每个维度一个"合法休息点"，惩罚错维度使用。

## 6. 世界保存（理解设计动机，不复制格式）

### 6.1 区域文件（Region/Anvil .mca）

- 概念：一个 `.mca` 文件打包 **32×32 = 1024 个区块**，覆盖 **512×512 方块**区域；文件名 `r.<rx>.<rz>.mca`；区域坐标 = 区块坐标 >> 5（有符号右移避免负数除法问题）。
- **文件头 8 KiB = 两个表**：
  - 位置表（4 KiB）：1024 个大端 32 位条目（3 字节扇区偏移 + 1 字节扇区数），单区块上限 256 扇区 = 1 MiB
  - 时间戳表（4 KiB）：记录各区块最后修改时间
- **4 KiB 扇区对齐**（与内核内存页一致）；区块数据 = 4 字节长度 + 1 字节压缩类型（2=Zlib 官方默认，4=LZ4 可选，3=未压缩，127=自定义）+ 压缩 NBT；尾部补齐到 4096 倍数。
- 设计动机：取代 Alpha 的"每区块一文件"以消除海量小文件的文件系统开销（官方称比旧系统快最多 7 倍）；稀疏扇区分配 + 追加写实现"分区块压缩、按需定位"。
- Anvil（1.2.1, version 19133）相对 MCRegion 的改动只在区块格式：高度 128→256、方块 ID 256→4096（Add 层）、**排列 XZY→YZX（改善压缩）**、空 section 不写入磁盘、群系按列 16×16 存储。
- OpenCraft 可自行设计容器（例如同样思路：区域打包 + 索引表 + 扇区对齐 + per-chunk 压缩），用 zstd 而非 zlib。

### 6.2 存档目录组织（Java 版 saves/<world>/）

```
saves/<world>/
  level.dat            # 全局 NBT：种子、时间、难度、游戏模式、生成设置、世界出生点
  level.dat_old        # 备份
  region/              # 主世界 .mca
  DIM-1/region/        # 下界
  DIM1/region/         # 末地
  entities/            # 1.17+ 实体独立区域文件（减小区块 I/O）
  poi/                 # 兴趣点（床、工作方块、蜂巢等，供村民 AI 寻路）
  playerdata/          # 每玩家 NBT（<uuid>.dat）
  stats/               # 统计 <uuid>.json
  advancements/        # 进度 <uuid>.json
  datapacks/           # 数据包
  icon.png             # 世界缩略图
```

### 6.3 NBT 与实体

- NBT（Named Binary Tag）：树形标签系统（复合标签、列表、各类数值/字符串/字节数组/长整型数组 IntArray 11 号由 Heightmap 使用）。是 MC 一切持久化的载体。
- **实体与区块分离存储**（1.17+）：实体不再是区块 NBT 的一部分，避免"为读实体加载整个区块"的 I/O 放大——OpenCraft 建议直接采用"方块/实体/兴趣点分库"的设计。
- 区块 NBT 核心内容：section 列表（含方块调色板 palette + 位打包数据 data）、高度图 Heightmap、群系、TileEntities、实体（旧版）、InhabitedTime（区域难度用）。

## 7. 游戏内容组织

### 7.1 游戏规则（Gamerule）

- 定义：世界级开关/参数，通过 `/gamerule <rule> <value>` 或创建世界界面设置；类型为布尔或整数；随存档保存在 level.dat。
- 分组（JE）：Chat / Drops / Miscellaneous / Mobs / Player / Spawning / World Updates。
- 代表性规则与默认值：
  - `keep_inventory=false`、`mob_griefing=true`、`do_daylight_cycle=true`（JE 26.x 更名为 advance_time）、`do_weather_cycle=true`
  - `random_tick_speed`：JE 默认 **3**/section/tick（BE 为 1）
  - `max_entity_cramming=24`（超出每 0.5 秒 6 点伤害）
  - `players_sleeping_percentage=100`、`spawn_radius=10`、`pvp=true`、`do_insomnia=true`（幻翼）、`raids=true`、`universal_anger=false`、`natural_regeneration=true`
  - `max_command_sequence_length=65536`、`max_block_modifications=32768`
- OpenCraft 建议：gamerule 就是一个注册表 + 序列化的键值集合；每个规则带类型与默认值，允许数据包级扩展。

### 7.2 难度机制

- 四档：**和平 / 简单 / 普通 / 困难**（`level.dat` difficulty 0–3；另有 hardcore=1 硬核标志，非独立难度）。
- 伤害：简单 = min(D, 0.5D+1)，普通 = D，困难 = 1.5D，和平无伤害。
- 饥饿：简单饿到 10 HP 止；普通到 1 HP；困难可饿死；和平不消耗饥饿。
- 特性差异：普通僵尸杀村民 50% 变僵尸村民（困难 100%）；简单僵尸不破门/洞穴蜘蛛不中毒；困难僵尸可破门+召唤援军；袭击波数 3/5/7（+战旗等级）。
- **区域难度（Regional Difficulty）**：0.00–6.75，由"区块驻留时间（50 小时封顶）+ 世界天数（第 3 天起生效，63 天封顶，贡献 0.25）+ 月相（满月 1.0 → 新月 0.0）"构成；换算后简单 0.75–1.5 / 普通 1.5–4.0 / 困难 2.25–6.75。钳制版 CRD：RD<2→0，RD>4→1，中间线性。它驱动携带装备怪概率、蜘蛛增益等"世界越危险"效果——这是一个低成本高表现力的机制，OpenCraft 值得复刻思想。

### 7.3 游戏模式

| 模式 | ID (level.dat gametype) | 核心规则 |
|---|---|---|
| 生存 Survival | 0 | 生命/饥饿、采集合成、死亡掉落 |
| 创造 Creative | 1 | 飞行、无限物品、瞬间破坏（生命被隐藏而非不存在） |
| 冒险 Adventure | 2 | 默认不可破坏/放置；仅 `can_break`/`can_place_on` NBT 标签的物品可行——专为地图设计 |
| 旁观 Spectator | 3 (BE 6) | 穿墙飞行、隐身、不可交互、可进入实体视角 |

- 硬核（Hardcore）= 生存 + 锁定困难 + 单命（死亡转旁观/删除世界）。
- 默认模式 ID 5 = "Default"（跟随 level.dat 默认）。

### 7.4 进度（Advancements）

- **126 个进度（1.21.x）**，分 **5 个根标签页树**：
  - Minecraft（故事线）16 个 / Nether 23 个 / The End 9 个 / Adventure（冒险）47 个 / Husbandry（农业）31 个
- 结构：每个 tab 从一个 root 进度生长为树；进度间独立可乱序完成；root 需要 `background` 字段；9 个隐藏进度（完成后才可见）。
- 三档类型：普通（普通方框 "Advancement Made!"）/ 目标（圆角 "Goal Reached!"）/ 挑战（尖角 "Challenge Complete!"，紫色）；挑战类常给经验奖励（如 "How Did We Get Here?" **1000 XP**、"Hot Tourist Destinations"/"Adventuring Time" 500 XP、多数 50–100 XP）。
- 定义为 JSON（数据包 `data/<ns>/advancement/`），criteria 条件 + rewards（经验/配方/战利品表）；玩家完成状态存 `advancements/<uuid>.json`。
- OpenCraft 建议：进度树用"ID + 父引用 + 触发条件 + 奖励"的扁平表即可，UI 按树布局。

### 7.5 统计系统

- 分类：**General（custom 自定义）**、**Items**、**Mobs**。
- **9 种统计类型**：`custom / mined / broken / crafted / used / picked_up / dropped / killed / killed_by`；custom 约 **78 项**（繁殖、各类伤害、各类距离、睡眠、容器交互等）。
- 键格式 `A.B:C.D`，如 `minecraft.mined:minecraft.stone`。
- 单位：**距离以厘米存储（1 方块 = 100 cm）**、**时间以 tick 存储（1 tick = 0.05 秒）**。
- 保存：`stats/<uuid>.json`（含 DataVersion + stats 键值）。仅 Java 版有此系统。

## 8. 对 OpenCraft 的落地建议（小结）

1. **世界参数直接对齐**：Y -64~319、区块 16×384×16、海平面 63、昼夜 24000 ticks、月相 8、下界 0~127 & 1:8、世界边界 ±29,999,984——这些是玩家可感知的"手感常数"。
2. **群系系统照搬 6 参数 + 最近区间匹配**：温度/湿度/大陆性/侵蚀/怪异性/深度，实现简单、行为对齐度高；群系决定 surface rule + 生物表 + 结构表。
3. **地形用 3D 密度函数 + 高度偏置**：一套代码覆盖三个维度（主世界单偏置、下界双偏置、末地压缩岛）。
4. **结构用 spacing/separation/salt 网格 + 要塞同心环特例**；必须处理跨区块溢出的确定性。
5. **保存层自研但借鉴 Anvil 思想**：区域打包（32×32 区块）+ 索引表 + 扇区对齐 + per-chunk 压缩（建议 zstd）；方块/实体/POI 分目录存储。
6. **内容组织**：gamerule 注册表、难度 4 档 + 区域难度、4 游戏模式、进度树（5 分支 126 个量级）、9 类统计（距离 cm / 时间 tick）。
