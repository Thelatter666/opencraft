## 1. ★ 公共接口的形状，以及为什么这样切（卡面要求说明）

### 1.1 最终形状

`engine/physics/include/opencraft/physics/sweep.hpp`（新增，195 行，header-only，只依赖 `IBlockSource`）：

```cpp
struct Box { double min_x, min_y, min_z, max_x, max_y, max_z; };            // 统一类型（两处旧定义字段完全相同）

Box    box_of(const glm::dvec3 &position, double half_width, double height); // 由脚底中心点 + 尺寸造盒

bool   box_collides(const IBlockSource &world, const Box &b);                // 严格重叠（面贴面不算）
double highest_surface_below(const IBlockSource &world, const Box &b,
                             double from_y, double bottom_y);                 // 高度感知的落地面

struct AxisSweep { double delta; bool hit; bool ground; bool ceiling; };      // "这次移动发生了什么"

AxisSweep sweep_axis_y(glm::dvec3 &position, double half_width, double height,
                       const IBlockSource &world, double dy);
AxisSweep sweep_axis_x(...);  AxisSweep sweep_axis_z(...);
```

`player_physics.cpp` 与 `item_sim.hpp` 各自只保留**薄包装**：前者把 `PlayerState` 的尺寸
（`kHalfWidth` + 随姿势变化的 `height()`）和**玩家的碰撞响应**（把刚损失的速度分量清零）留在自己这边；
后者把**掉落的碰撞响应**（`-v × restitution`，T-D36 项 1）留在自己这边。

### 1.2 为什么这样切（五个决定 + 各自理由）

1. **只抽"几何"，不抽"响应"**。玩家撞墙是把该分量清零、掉落物是乘 restitution（校准旋钮）。
   这是内容差异而不是几何差异；把它一起抽走会让一个"纯重构"卡悄悄决定两种手感中的一种。
   证据：`item_sim.hpp` 里 `rules.restitution` 的调用位置与语义**逐字未动**（compare.out 的 ledger）。
2. **逐轴原语，而不是一个合并的 `sweep_move(pos, dx, dy, dz)`**。三个调用方形状不同：
   玩家的 step-assist 会**单独重算 X+Z**（`resolve_horizontal`），玩家的 Y 调用方要自己记账
   `hit_ground/hit_ceiling/on_ground/fall damage`，掉落物则在三轴之间插入自己的 restitution。
   合并版最终必须返回逐轴 flags 并让调用方拆开，等于把同样的信息包一层 —— 逐轴是最小的共享面。
3. **返回 `AxisSweep` 而不是沿用 `bool &` 出参**。旧 `move_axis_x(..., bool &hit_wall)` 的语义是
   "置真"，而玩家的 `hit_x` **跨子步累积**（同一个变量被 4 个子步复用）。若共享实现继续用"置真"，
   调用方就无法区分"这一次撞了"与"上一次撞过"；若用 `if (hit_wall) 清零速度` 就会在未碰撞的子步上误清零。
   返回每次调用的结果让两边都能精确表达自己的响应（掉落物用 `y.hit`、玩家用 `swept.hit`）。
4. **`box_of(position, half_width, height)`，而不是让 physics 认识 `PlayerState`/`EntityDef`**。
   依赖方向是**实体 → physics**（卡面设计约束）。玩家高度随姿势变（1.8/1.5），实体高度来自 `EntityDef`，
   把尺寸当参数传进来，physics 头文件不需要知道任何一种身体。`IBlockSource` 的
   `solid_at` / `shape_top_at` / `liquid_at` **一字未改**（`block_source.hpp` 本卡零 diff）。
5. **`EntityBox` 直接删除、不保留别名**。"成为别名"同样满足卡面，但别名会留下**同一个类型的两个名字**
   —— 那正是这次重复的起源（两个名字 → 两份实现 → 两处语义）。现在全仓只有 `physics::Box` 一个名字。

### 1.3 受影响的调用点（old → new）

| 位置 | old | new |
|---|---|---|

### 1.4 那一处"看起来像改写、其实等值"的地方（主动交代）

旧玩家侧 Y 轴回落有一处多余的整数往返：
`static_cast<double>(static_cast<int>(std::floor(x))) + 1.0`。共享版写成 `std::floor(x) + 1.0`。
对 `|x| < 2^31` 两者**逐 bit 相同**（`floor` 的结果是精确整数、`int` 往返无损），
世界 y 坐标在该范围内；轨迹 A/B 里两个"落到 0.25 半砖面"的算例（玩家 与 掉落物）
都精确落在 `64.25`（bit `0x4050100000000000`），与新老实现一致。除此之外**没有第二处改写**。
