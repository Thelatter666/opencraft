## 来源等级说明

- **原文**：自 rollout 记录提取的卡面文本**逐字照抄**，未润色、未改错别字、未合并当时的
  矛盾表述。提取脚本：`/Users/happy/.zcode/tmp/opencraft-extract-cards.py`（只读 rollout 记录，不写仓库）；
  索引由脚本生成于 `/tmp/opencraft-tasks/INDEX.md`，重跑产物与首跑逐字节一致。
- **原文缺失 → 事后要点摘录**：保留的记录中没有该卡原文（T001、T002）。此类文件**不是派发原文**，
  正文只含可从 git 历史核实的事实（提交号、变更文件、验收计数），**不复述"当时要求了什么"**。
- **未派发**：尚未拆卡（T-D1），无文件。
- 历史的中间轮次可能被压缩过，故卡面副本长度可能不一致；选择规则为"取小节最全、其次最长"。

> **来源等级为自动判定，须人工核对。** 本表等级已人工核对过一轮（原文类均抽查过正文，
> 缺失类已确认记录中确实没有），但后续新增卡面仍须逐张复核。

## 规则（自 T010 起生效）

1. **先落盘再转发**：卡面文件先写入并提交，再输出给用户转发，二者内容一致（消除转录差）。
2. **卡面不写状态**，只写"要做什么、怎么算过"；状态唯一权威仍是 `STATE.md`。
3. **卡面是派发时点快照，不得改正文**；一切修订追加「变更记录」（日期、内容、依据、授权）。
4. **开发者报告一律落 `docs/tasks/T<ID>.report.md`**（2026-09-14 起，跨 agent 需要）。
   同 agent 内转发时代可只贴对话，但落盘是默认——PM 可能看不到开发者的对话（跨 agent 场景），
   文件是唯一可靠通道；报告另有版本历史，便于验收争议时回溯。
5. **路径一律写完整绝对路径**（如 `/Users/happy/Desktop/opencraft`），不用家目录简写 `~`——
   同一份文档可能被其他工作区/其他机器上的会话读取，简写会变成悬空指针。
   *（例外：本目录中作为**逐字快照**归档的卡面正文，即使含 `~` 也保持原样不改。）*
