## 3. 七条裁决（PM 已裁，照做）

### C-1 物品移动 UI = 复用现成模型函数，光标堆是唯一新概念

- **左键**点击格：光标空 → 整堆拿起（`slot`→cursor）；光标非空 → 同物合并（`move_slot` 语义）/
  异物交换（`swap_slots`）；点到空格 → 整堆放下。
- **右键**点击格：光标空 → 拿**半堆**（`ItemStack::split`，向上取整）；光标非空 → 放 **1 个**
  （格可叠则并入）。〔research 无来源，MC 同类手感，自定标注 §2.3〕
- 光标堆在界面打开期间存在；关闭界面（E/Esc/右键工作台关闭）时**光标堆必须归还背包**
  （`add_item`，装不下就地掉落——复用 `spawn_item_drop`？不行，那是权威侧；客户端拿不掉的
  堆在关闭时**禁止关闭**（提示格满）——取简：先 `add_item`，失败则保持界面打开）。
- 盔甲格/副手格**照常显示**但本卡不做装备交互（拿起/放下对盔甲格放行 `accepts` 校验即可——
  穿上即生效是 T-D46 已有逻辑，**顺手可通**，不算越界）。

### C-2 合成在**客户端本地**结算，不走权威侧

合成是纯背包操作（不动世界），符合 T-A1 的拆分惯例（拾取 dry-run、容器转换都在客户端本地）。
工作台**方块**的放置/挖掘走既有 `PlaceBlock`/`Dig`（权威侧）；3×3 界面读的是**打开时客户端
已有的本地库存**——单人进程内两侧同库，M3 网络化时合成请求才需要上收（登记为 M3 备注）。

### C-3 E 界面的输入门控（★ 不做这步会出"隔着界面挖方块"）

`TickContext`（`tick.hpp:33-58`）加 UI-open 标志；`run_tick` 里**全部世界交互**（攻击/挖掘/
放置/拾取/喂食）在该标志下**短路**（与死亡态的 `may_act` 同型单一早退）；鼠标看向在 main 侧
加第三 clause（仿 `main.cpp:523`）。**单测必须证明**：界面打开时提交 Dig/PlaceBlock/Attack
请求被拒或根本不产生。

### C-4 配方引擎：shaped 用"归一化最小包围盒 + 平移 + 水平镜像"，shapeless 用多重集

- shaped：把网格裁到最小包围盒 → 与配方模板比对（允许平移、允许**水平镜像**、**禁止垂直
  镜像**——`research/11:412-414` ⚖ 已核验；3×3 配方在 2×2 网格内因尺寸自然不匹配）。
- shapeless：材料多重集相等即命中（`1 原木→4 木板`，`research/11:420`）。
- 多配方同网格冲突时**无解报错**（首发 11 条经卡面 §4.1 互斥核算，不存在冲突）。
- 配方表 = `game/common/` 新 `RecipeRegistry`（数据驱动，照 ItemRegistry 惯例：字符串 id、
  重复/空 id throw）。

### 4.1 权威算例（PM 已算，可直接写成断言）

**挖掘时间**（docs/01:68：`硬度 × (可采收 ? 1.5 : 5) ÷ 倍率`；石头硬度 1.5）：

| 场景 | 时长 | 掉落 |
|---|---|---|
| 徒手挖 stone（等级 0 < 1） | 1.5×5/1 = **7.5 s**（150 tick） | **无** |
| 木镐挖 stone（tier 1 ≥ 1） | 1.5×1.5/2 = **1.125 s** | rubble_rock ×1 |
| 石镐挖 stone（tier 1，速度 4） | 1.5×1.5/4 = **0.5625 s** | rubble_rock ×1 |
| 木镐挖 iron_ore（tier 1 < 2） | 3.0×5/1 = **15 s** | **无**（石镐 1.5×1.5/4 = 0.5625 s 有掉落） |
| 徒手挖 log（等级 0） | 2.0×1.5/1 = **3 s**（现状不变） | timber_log ×1 |

**配方消耗算例**（C-5 斧：3 材料+2 棍）：网格中 5 格各扣 1 → 一次合成消耗 3 板 2 棍出 1 斧；
材料不足任一格 = 无产物。

## 7. 已知风险与提示

1. **UI 状态机是本卡最险的部分**：光标释放/回收的边沿交接（`main.cpp:480-500` 先例）、
   HiDPI 命中换算（`pause_menu.cpp:32-38` 先例）、UI-open 门控（C-3）三件事交织——
   先把死亡画面的模态骨架读透再动手。
2. **`ItemRegistry::create_default()` 自建 BlockRegistry 解析 block 字段**——方块行与物品行
   必须**同一提交**（否则 `id_of` throw，构建红）。
3. **atlas 数字是连锁后果**：加方块后 `crack_tile_base` 63→66，任何"裂纹贴图索引"相关断言
   都要跟着走；图集尺寸不变（76 瓦片仍 9 列），加到 24 方块才会翻 10 列（那时另算）。
4. **金矿等级疑点**（C-6）按保守值 2 落，标注待校准并入 T-D36；**不要**按 research/01:138
   字面把金矿做成石镐可挖。
5. **石档工具的攻击数值**（C-5）是本卡顺手落的（:172 成品值：剑 5/斧 9/镐 3/锹 3.5）。杀 20 血
   Hollow Wretch 的击数对比（PM 已算，单测直接钉）：**石剑 5 伤 = 4 击、木剑 4 伤 = 5 击、
   徒手 1 伤 = 20 击**；斧 9 伤 = 3 击（20/9 = 2.22 → 3）。
6. 启动包收回剑/锹后，**开局玩家没有任何剑**——真人验收时这是预期（进程线起点），不是缺失。
7. 本项目纪律：任何"不存在"给检索式留痕（本卡面 §2.2 即样本）；构建禁接管道；
   主仓 build 已固定带离线 deps configure 变量（T-D59 起的惯例），worktree 仍不设
   `FETCHCONTENT_BASE_DIR`。
