### ★ 目标栈并发（本卡最易错点）—— 自写探针实测

```
场景A（高优先级 TargetPlayer 在跑 + 两个低优先级可跑）
  ⇒ 同时在跑的目标数 = 3  ✓ 并发成立
场景B（同优先级 2/2，都未跑）

```

**这正是 `research/11 §1.4` 要求的语义**（若实现成"只跑第一个"，
僵尸将永远只会反击、不游荡不环视——行为明显不对）。

排序用**优先级 + kind 双键**（避免非全序导致的偶然耦合）。⇒ 设计干净。

## 建议处置

### R-1（建议立案）：`PhysicsConfig` 缺 per-entity 体形 —— **采纳，登记 T-D42**

他指出：补 `half_width`/`height` 后，下一张卡可整段复用玩家管线。
**这是很有价值的观察**——`EntityDef` 已有体形，但 `PhysicsConfig`/`step_player`
是按玩家体形硬编码的，导致生物无法复用。

**裁决：采纳，登记 T-D42（中）**。
这属于"参数按实体类型实例化"（`docs/03 §6` 冻结契约）未完全落实的部分。

### R-3（建议立债务）：生物与玩家无碰撞 / 无摔落伤害 / 玩家无死亡状态 / 无无敌帧护甲击退 —— **采纳，拆分登记**

这四项其实是**不同性质**的缺口，我拆开登记：

| 债 | 内容 | 优先级 |
|---|---|---|
| **T-D43** | 生物与玩家无碰撞（实体间碰撞缺失） | 中 |
| **T-D44** | 生物无摔落伤害 | 低 |
| **T-D45** | 玩家无死亡状态（HP 到 0 无后果） | **中高**（生存循环缺口） |
| **T-D46** | 无受击无敌帧 / 护甲 / 击退 | 中（战斗卡） |

⇒ T-D45 优先级最高：**没有死亡状态，生存循环不成立**。应尽早补。

### R-5（入 `docs/05 §3.1`）：三条取证经验 —— **采纳，当场落盘**

- 合成鼠标移动本机**严重非线性**（30 px 可打到 89° 钳位）⇒ 瞄准改用潜行水平视线
- HUD 第 N 格 = 槽 N−1
- `screencapture` 对非前台窗口返回**旧表面**

这三条都是"会让取证结论伪造"的坑，**当场写入 `docs/05 §3.1`**。
