## 目标
建立体素世界的数据层：16×384×16 区块（24 个 16³ section）、section 级方块调色板、
方块注册表（字符串 ID→运行时数字 ID）、区块管理器。本任务只做"数据 + 存取 + 序列化"，
不做地形生成、渲染、光照（后续任务消费你定义的接口）。

## 接口契约（冻结项，T004–T009 将直接依赖）
- 命名空间 `opencraft::voxel`；库 target `opencraft_voxel`，链接 `opencraft_core`。
- 常量：`Chunk::kSizeX=16, kSizeY=384, kSizeZ=16`；section 16³、每区块 24 个；
  section 内存储布局 **YZX**（docs/research/02 §1.1：同列方块相邻，为压缩服务）。
- `BlockRegistry`：注册接口 `register_block(std::string id, BlockDef)` → 运行时 u16 ID；
  `BlockDef` 至少含：显示名、是否实心（碰撞）、是否透明（光照/网格化用）、硬度（float，
  用 docs/research/01 §5.2 表：石头 1.5、泥土 0.5、原木 2.0 等，值可先填 ~20 种）；
  id → ID 与 ID → id 双向查询；`air()` 为 0 号保留 ID。首发方块 ~20 种
  （土/草/石/沙/砂砾/原木/树叶/木板/水/基岩/圆石/煤矿/铁矿/金矿/钻石矿等，命名原创，
  允许先用占位英文 id 如 "dirt"，不使用 Minecraft 专有名称）。
- `Chunk`：`get_block(x,y,z) -> u16` / `set_block(x,y,z,u16)`（区块内局部坐标，
  越界断言/抛异常）；`section_empty(i)` 快速判空；坐标编解码
  `chunk_coord(world_x,world_z)`（含负数正确向下取整，必须单测负坐标）。
- `ChunkManager`：`unordered_map` 或等价稀疏容器按 (cx,cz) 管理 `unique_ptr<Chunk>`；
  `get_or_load(cx,cz)` 允许本任务只做"不存在则返回 nullptr 或创建空块"（生成接入是 T004 的事）。
- 序列化：`Chunk` ↔ ByteBuffer 双向（版本前缀 + 仅写非空 section + 调色板内容 + 位打包数据）。
  格式细节自定，但必须带格式版本号。

## 已知风险与提示
- 调色板位宽实现自定：单一 u16 数组起步也可以接受（先正确后优化），但接口要允许
  后续换紧凑位打包而不破坏调用方——把存储细节藏在 Chunk 内部。
- 水是"非实心但非空气"，会影响后续光照/网格化判断——注册表里的 is_solid/is_transparent
  两个字段要分开，不要合并成一个布尔。
- 序列化布局 YZX 只影响字节序节省压缩率的动机，本任务还没接 zstd，按 YZX 写即可。
- 不引入 zstd/EnTT 等新依赖（区域文件+zstd 是 T009 的事）。
