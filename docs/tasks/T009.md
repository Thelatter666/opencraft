## 接口契约（冻结项）
- 命名空间 `opencraft::storage`（新库 target `opencraft_storage`，链 core+zstd+voxel）。
- 区域文件：`RegionFile`（打开/读区块/写区块/区块是否存在），路径 `<saves>/<world>/region/r.<rx>.<rz>.ocr`；
  level 文件 `<saves>/<world>/level.ocd`（全局状态+玩家数据，允许 JSON 或二进制自定，
  带格式版本）；世界目录名本卡固定 "world"。
- 写入协议：先写临时文件 → fsync → 原子 rename；索引表与扇区分配自定但必须在头部可校验
  （魔数+版本+校验和），损坏文件能被检测并拒绝加载（报错不崩溃）。
- 存档内容最小集：修改过的区块（含调色板+光照可选）、玩家状态、种子、游戏内 tick 计数。
  未修改的区块不落盘（重进时由种子重新生成——确定性由 T004 黄金测试保证）。
- 自动保存节奏：脏区块集合每 ~10 秒批量异步写（独立低优先级线程，task_system 已有），
  退出/暂停菜单 QUIT 时强制 flush。

## 验收标准（逐条可执行）
1. worktree 短分支 `task/T009-persistence`，提交以 `taskT009:` 开头。
2. 干净构建零错误零警告（第三方 cmake 弃用提示除外）；`ctest` 全绿，133 个存量零回归。
3. 单元测试：区域文件读写回环（多区块、复写同区块、跨扇区增长）；损坏检测（截断文件/
   错魔数/错版本 → 拒绝且不崩溃）；level 文件回环（玩家状态字段逐项）；zstd 压缩后
   与 T003 的 8253 字节典型区块对比报告压缩率。
4. **端到端存读档（核心验收，报告附证据）**：
   a. 新档进入 → 移动/挖掘若干方块/放置若干方块 → 暂停菜单 QUIT → 重启程序 →
      进入同一世界：改动全部还在、玩家位置恢复；
   b. **崩溃恢复**：游戏中 `kill -9` 进程 → 重启 → 脏区块最后一次自动保存之后的部分
      允许丢失（报告说明丢失窗口≈10s），但文件不损坏、能正常加载；
   c. 未修改区块重进时不重新生成（日志或计数证明读盘命中）。
5. P2 修复证据：ESC→暂停→ESC→恢复→ESC→暂停→QUIT 全链路截图或日志；PM 会用
   System Events 键盘（key code 53）实机复测双向切换，请确保该路径可用。
6. HUD：快捷栏/生命条/挥手动画/破坏粒子实机截图各一张。
7. 测试名避 `[`；clang-format 通过；**报告整体放单个 markdown 代码块**。

## 已知风险与提示
- zstd：BSD 许可，报告注明来源与版本；压缩级别 3 左右即可（速度优先）。
- 光照数据本卡可选落盘（不落则重进时重算，T006 init 1.3–8.8ms/区块可接受）——二选一写明。
- 区块卸载钩子（T006 留）：卸载时若有脏数据先落盘再释放，防丢档。
- 异步写与主线程的世界状态并发：用"拷贝快照再写盘"（task_system 提交拷贝任务），
  不要让 IO 线程直接摸 ChunkManager。
- spawn 5×5 安全扫描（T004 备忘）本卡顺手做掉：出生点改为扫描地表最高实心方块。
- 疾跑跳位移增益等物理项不在本卡范围。
