## 目标（一段话）

建立 OpenCraft 的**实体层**（目前完全不存在），并在其上实现**掉落物实体**
（重力/滑行/拾取/合并/超时消失）。这是 M2c 全部内容（生物 AI、战斗、掉落）的前提。

```

```

不先建实体层就做生物/战斗，等于把实体逻辑散落在各处，
后面每张内容卡都要自己造一套（这正是我们一直在避免的"双重真相源"）。

用户裁决「结构优先」，故本卡排在 M2c 内容之前。

### ★ 掉落物物理参数（research/11 §4.1，逐条引用）

| 项 | 值 |
|---|---|
| 重力 | **−0.04** 格/tick²（**不是**玩家的 −0.08） |
| 阻尼（垂直 / 水平） | **0.98 / 0.98**（**不是**玩家的 0.91） |
| 终端速度 | 39.2 m/s |
| **执行序** | **A → P → D**（先加速、后位移、最后阻尼） |

⚠ **执行序与玩家不同**：玩家/生物是 **P → A → D**。
**顺序错了落点会偏。** 这与 `docs/03 §6` 冻结的"阻尼在位移之后"是同一约束的两种表述
（掉落物同样满足"阻尼在位移之后"，只是加速在位移**之前**）。

- 水平阻尼 0.98 而非 0.91 —— 这就是掉落物能在地上滑很远的原因。

### 拾取与合并（research/11 §4.2–4.4）

| 项 | 值 |
|---|---|
| 掉落物碰撞盒 | **0.25 × 0.25 × 0.25** |
| 玩家拾取盒 | 玩家碰撞盒**水平外扩 1 格、上下外扩 0.5 格**；水平**含**边界（≤1），垂直**不含**（<0.5） |
| 拾取延迟 | 自然掉落 **10 tick**；玩家投掷 **40 tick** |
| 合并周期 | **每 40 tick**；跨方块边界时可 **每 2 tick**；传送后立即尝试 |
| 合并规则 | 同类型 + 可堆叠 + 合并后不超上限；**数量多的那个**保留，另一个消失；计时器取**剩余更长**的 |
| 超时 | **6000 tick（5 分钟）**；仅已加载且处理实体的区块内计时，**区块卸载则暂停** |
| 环境伤害 | 掉落物有 **5 点生命**，被火/岩浆/仙人掌/爆炸摧毁；**不可被玩家或生物攻击** |
| 免疫 | 下界合金类免疫火、浮在岩浆上；**伤害性方块**（岩浆块/营火/甜浆果丛/凋零玫瑰/细雪）**不伤害掉落物** |

### ⚠ 三处待校准（T-D36，**不得编造**）

1. **弹性系数（弹跳）**：wiki 无来源。`docs/01 §5` 写的"有重力与弹跳"中**弹跳无依据**
   ⇒ **先取 0（不弹跳）**，实机手感校准后再定。
2. **着地摩擦修正**：玩家/生物着地时水平阻尼为 `0.91 × friction`；
   掉落物是否有同样修正 wiki 未说 ⇒ 先按 `0.98 × friction` 实现并标注待校准。
3. （本卡不涉及逃跑速度倍率，那是生物卡的事）

⇒ 这三条**写进代码注释**，并在报告中申报。

## 附：为什么实体层要单独一张卡

`docs/03 §6` 的架构意图（EnTT ECS / 行为树 / 实体与方块分面）**从未落地**。
带着这个缺口做生物 AI，会把实体的存储、遍历、碰撞散落在生物逻辑里——
等后面要加战斗、投射物、载具时，每加一个都要返工。

本卡把这块地基单独做掉，后面的生物卡（T-M2）就能专注在 AI 本身。
