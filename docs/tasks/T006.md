## 目标
实现 15 级双通道光照：skylight（列直射 15、向下无衰减、横向扩散 -1）与 blocklight
（光源 BFS 每格 -1），存储进区块，支持方块修改后的增量更新（含"暗度删除 BFS"），
跨区块传播走延迟队列。本任务交付数据层与算法，不接渲染（T005 之后由集成任务消费）。

## 接口契约（冻结项）
- 命名空间 `opencraft::voxel`（并入现有 voxel 库）；核心类型：
  - `LightStorage`：每方块 2×4-bit（sky/block 各 0–15），支持按区块/世界坐标读写，
    序列化可选（本任务不强制落盘）。
  - `LightEngine`：构造持有"世界访问接口"（区块查方块透明性/光源等级的回调或接口，
    自定，但要能脱离 ChunkManager 单测）。
    方法至少：`init_chunk(cx,cz)`（列天光直射+边界种子）、
    `on_block_changed(wx,wy,wz, old_id, new_id)`（增量更新入口）、
    `light_at(wx,wy,wz) -> {sky,block}`、`pending_count()`（跨区块延迟队列诊断）。
  - 光源等级：注册表当前无光源方块，接口按"方块 ID → 发光等级"的函数/表注入，
    默认全 0；测试里注入虚拟光源表（如某 id 发 14 级）。
- 传播规则：显式队列 BFS（禁止递归）；天光向下不衰减、横向 -1；不透明方块阻断；
  删除用暗度 BFS + 边界重加光。

## 已知风险与提示
- 暗度删除 BFS 是最容易错的部分：删除队列记录旧光值，扣到 0；凡"本来还有别的光源
  可达"的格子要转重加光队列——research/03 §2.2 引用的社区讨论可参考（只看思路）。
- 跨区块延迟队列要能去重（同一邻区多次触发改只投一次），否则方块级联修改会雪崩。
- 天光高度图缓存建议做（每列最高不透明方块），不做也能过验收，但报告里说明取舍。
- 不要动 T005 的 meshing、不要接渲染；不要改 Chunk 序列化格式（v1 保持稳定）。
