## R2. 7.127 m/s 实测未达标（报告 §3 的解析表有误）

**实测**：`sprint_jump_boost = 0.146` → 弧均速 **6.6989 m/s**，比 ⚖ 目标 7.127 低 **6.0%**
（测试 #127 失败）。报告 §3 的解析推导（0.146 → 7.127 ±0.2%）与实现不符，**不得据此收口**。

**裁决**：⚖ 值必须命中，不接受"等 T-D7 迁移后自然命中"。理由：docs/01 §2 的 7.127 是可观察
规格值，M1 已按此口径验收；若把 6.7 合入 main，⚖ 标记就失去约束力。

**方向**（未实测，仅作起点，必须自行实测标定）：按本引擎管线复算，命中 7.127 约需
`B ≈ 0.163`，对应净跨距 4.03（仍在 3.7–4.3 窗口内）；但该复算与实测存在约 0.22 m/s 的
系统性偏差，**实际值可能落在 0.17–0.19**。请扫描实测曲线取点，不要直接用 0.163。

## R3. 测试 #129 弧长窗口 off-by-one（必改）

`s.on_ground` 在循环第 12 次（t=11）已为真——本引擎的滞空段是 **12 个 move**（起跳 + 11），
不是 13。测试 #127 按 13 个 move 取样，末段把落地后的地面 tick 算了进去，这会系统性压低均值
（可能是 R2 偏差的组成部分）。

**裁决**：先写一个逐 tick 打印 `on_ground / y / vx` 的诊断（可临时，不必入库），**用实测确定
弧长**，再据以校准 `sprint_jump_boost` 与取样窗口。窗口错了，标定的数就是错的。

## R4. 黄金回放 #72（授权重生成，但须逐 leg 交代）

测试 #72 失败于 `t=400` 空中段（`vel.x -0.243635` → `-0.244512`），与报告 §5 预判一致：
空中模型由"锚定步行速度"改为 MC 常数 `air_accel = 0.02` 导致。**这是预期的、本卡想要的漂移。**

**裁决**：批准 `air_accel = 0.02` 换轨（调研支撑充分，且修掉了 T007 遗留的"疾跑跳掉回步行
速度"问题）。授权 `OPENCRAFT_PHYSICS_UPDATE_GOLDEN=1` 重新生成黄金值，但报告必须**逐 leg
给出旧值→新值与原因**，不能只交一个新 hash。

## R5. §4 架构决策点：采纳方案 A，附加强制条件

**采纳 A**：本卡按当前管线收口；迁移 MC 摩擦管线另立独立卡 **T-D7**（已登记）。

强制条件：
1. 本卡结束时 ⚖ 验收（7.127 ±1%、≈4 格跨距）必须实测通过（见 R2）。
2. `sprint_jump_boost` 的注释必须写明**它是本引擎简化管线的校准值、以及退役条件**
   （T-D7 迁移后 MC 原始 +0.2 应能自然命中）。
3. T-D7 的验收项之一：**迁移后 +0.2 命中 7.127**，届时校准系数退役。

不采纳 B：一次到位会让黄金回放全量重推导、改动面翻倍、145 存量测试的验收风险显著上升，
不符合"一次不铺太大"。
