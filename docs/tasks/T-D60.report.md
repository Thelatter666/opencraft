## 6. ★ 与卡面的偏差 / 需 PM 裁决（4 项）

### 6.1 采集等级口径：卡面四处表述互斥，本卡按 §4.1 收敛（**需确认**）

卡面同时给出：`ItemDef::mining_tier` "0=徒手档"（C-6）、工具档 "木 0/石 1/铁 2/钻 3"（C-6，与
research/01 §9 一致）、需求表 "石族=1、煤/铜/铁矿=1、金/钻石=2、黑曜石=3"（C-6）、
以及 §4.1 的验收表（徒手挖石失败而**木镐成功**）。四者不能同时成立：

- 若徒手 = 0 且木镐 = 0，"徒手失败、木镐成功"无法用单一比较 `tier >= 需求` 表达（契约⑦）；
- 若石族需求 = 1，则木镐（0）也挖不动石头，§4.1 第二行与整条进程链（木镐→圆石→石镐）断裂。

**本卡取**：工具档照 §9 Tiers 原样 0 基（木 0 / 石 1）；**徒手 = `kNoTool` = -1**（在表外、
比最低档更低）；需求表用同一 0 基刻度，**石族/煤矿 = 0**（木镐），铜/铁矿 = 1（石镐），
金/钻石 = 2（铁镐；金 = PM 的保守值，标注待校准），黑曜石 = 3（钻镐）。
这样 §4.1 五行**全部成立**，且契约⑦的单一比较成立，`harvest_level("stone")` 也从"需工具"变成
0 而不是新增第二个标志位。

⇒ 与 C-6 字面的差异只有两处：`ItemDef::mining_tier` 的**默认值**（-1 而非 0）、
**石族与煤矿**（0 而非 1）。若 PM 坚持字面值，则 §4.1 第 2 行与 C-5 的进程链需要一并改写——
**请裁决**。

### 6.2 §4.1 第 4 行的"石镐 0.5625 s"是算术笔误（**已在报告中更正，未改卡面**）

铁矿硬度 3.0：`3.0 × 1.5 ÷ 4 = 1.125 s`（0.5625 s 是上一行石头的 `1.5 × 1.5 ÷ 4`）。
该行要证的**门控**（木镐无 / 石镐有）已逐字实现；时间按 1.125 s 钉死（23 tick）。

### 6.3 关闭界面的"右键"路线移除（**需确认**）

C-1 括注"E/Esc/**右键工作台**关闭"。但 C-3 要求 UI-open 期间世界交互全被门控 ⇒ "右键工作台方块"
这条路径在本卡的前提下**不可达**。我一度实现为"右键点在面板外即关闭"，实机测得**缺陷**：
打开工作台 3×3 的那次右键会在下一帧落到同一条规则上、把刚开的界面关掉（日志相隔 **0 ms**）。
现取：**关闭 = E / Esc**（基版自己退出容器界面的两个键）+ 死亡强制关闭。
⇒ 若 PM 要保留鼠标关闭，请指定一个不与"点开界面"冲突的手势（例如 Shift+右键）。

### 6.4 契约②的"恰 5 个物品"与方块形态行

按契约①"方块行与物品行必须同一提交落地"，`assembly_bench` 需要一个**物品行**（否则方块可放
不可得）。故本次**物品行净增 6**：5 个内容物品（`timber_stick` + 石档四件）+ 1 个方块形态行。
契约②的"恰 5 个"理解为**内容物品**；若 PM 的口径是"物品行恰 5"，请裁决。

### 6.5 关闭时**网格**内容也归还（卡面只写了光标堆）

`crafting_close` 把光标堆**和**网格里剩下的材料一并 `add_item` 归还（失败则整体不动、界面保持
打开）。理由：屏幕关闭后网格里的物品既不显示也不可用，留着会变成"看不见的仓库"。卡面未裁此项，
**请确认**（若要保留在网格里跨开关保留，改动很小）。
