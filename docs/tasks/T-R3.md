## 2. 必须回答的六个问题（文档须逐条给出结论）

### Q1：体素模型 vs 盒式组合 —— 定下主方案

用户已裁决方向为 **`.vox` 体素模型**。本卡要把它落成可执行结论：

- 体素模型（MagicaVoxel `.vox`、体素网格）与 MC 原版式「盒式组合 + 骨骼」的**取舍对比**
- 明确推荐哪一种，并说明**代价**（顶点数、动画表达力、美术制作成本）
- ⚠ **不得**因为"更像 MC"就选盒式——本项目对齐的是**可观察行为**，外观须原创
  （`docs/04` 红线 5：观感不逐项对齐）

### Q2：模型文件放哪、叫什么

- 目录与命名（建议比照 T-A2 已成型的 `assets/blocks/<id>_<slot>.png` 风格）
- **是否纳入 T-A2 建好的资产根解析**（`$OPENCRAFT_ASSETS_DIR` → `<cwd>/assets` → `<cwd>/../assets`）

### Q3：动画方案

- 生物的哪些动作需要动画（至少：行走、转向/看人、受击、死亡）
- 体素模型怎么做动画：骨骼绑定？逐帧模型切换（`.vox` 的 `PACK` chunk 支持多模型）？程序化摆动？
- 与现有**模拟值**的关系：`main.cpp:706` 注释指出——**朝向是模拟值**（`Entity::ai::yaw`），
  不是渲染侧动画。⇒ 方案必须让"模型朝向"由模拟驱动，渲染侧**不得**自行发明朝向。

### Q4：加载器选型

- 自写 `.vox` 解析 vs 引入第三方库
- 若引入：**许可必须核到源码头部**（不能只看 GitHub API 的 `spdx_id`）
- 与 `docs/03 §9`「全部宽松许可」政策的一致性

### Q5：与现有渲染管线的接入点

- 现状：生物走 `crack_shader`（与掉落物共用），几何是 `cube_geometry.hpp` 的**单位立方体**
- 方案须说明：模型网格如何进入渲染（新 shader？复用？）、是否影响 `engine/render`
- ⚠ **本卡只做方案，不得改 `engine/render/**`**（那是后续实现卡的事）
- 必须评估：接入是否会让"两个立方体"的现有行为在**新模型未就绪时**崩溃
  ⇒ **回退策略**（缺模型文件时仍画立方体，比照 T-A2 的"缺 PNG 回退"）

### Q6：工作量与分批

- 3 种首发生物 + 后续生物扩展，美术侧与引擎侧分别多少工作量
- 建议的**分批顺序**（哪种先做、为什么）

## 3. ★ 必须先解决的许可问题（Q4 的前置，不可跳过）

PM 在 2026-09-18 已核的部分（**不要重复劳动，但要补完**）：

| 项 | 已核结果 | 核验方式 |
|---|---|---|
| `.vox` **格式规范**仓库 `ephtracy/voxel-model` | **MIT** | GitHub API `license.spdx_id = MIT` |
| 格式结构 | RIFF 风格；`MAIN` 根 chunk；`SIZE`(尺寸) / `XYZI`(体素: x,y,z,colorIndex) / `RGBA`(256 色调色板)；`PACK` 用于动画多模型 | `MagicaVoxel-file-format-vox.txt` 原文 |
| 解析库备选 | `eisenwave/voxel-io`（32★，MIT，C++17，含 VOX/QB/QEF）、`Deins/VoxReader`（0★，MIT） | GitHub API |

**❌ 未核、本卡必须查清**：

1. **MagicaVoxel 软件本身的许可**——PM 核查时官网 `ephtracy.github.io` 未列明许可条款，
   `LICENSE.txt` 404。**不得默认 CC0。**
   ⚠ **PM 自我更正**：PM 曾在对话中口头说 `.vox` "可用 CC0 工具链"，**该说法未经核验，是错误的**。
2. **工具许可 ≠ 产出许可**——即使制作工具免费/开源，**产出的模型仍是我们自己的原创资产**，
   受 `docs/04` 约束（不得接近原版生物外观）。这一点要在文档里写清楚。
3. 若 MagicaVoxel 许可不适合，需给出**替代制作工具**（开源/CC0/自制）及其许可核验。

> **核验手法提醒**（`docs/05` 既有教训）：
> - curl **必须加 `-x http://127.0.0.1:7890`**，否则 DNS 劫持到 198.18.0.35、SSL 35 报错
> - WebFetch 在 wiki 上必超时；查 GitHub 用 `gh api` 或 raw URL
> - **许可以源码头部自述为准**，GitHub API 的 `NOASSERTION` 只说明仓库含多许可
