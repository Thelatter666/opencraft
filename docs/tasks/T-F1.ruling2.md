## §0 PM 独立复现（关键，先于裁决）

技术工的证据分三层自标等级，其中"用户实机口述"被他正确标为**最低证据等级**（单方陈述、无留档）。
PM 因此**自己写探针实测**，把该症状变成可留档的机器产物：

```
平地 + 单个 1 格浅凹（源在 0,0，半径 5）：
  无凹（对照）           格数=113  +X=49 -X=49 +Z=49 -Z=49   四向 ✓
  凹在 +X 距3（半径内）   格数=  5  +X= 4 -X= 0 +Z= 0 -Z= 0   ★塌成单行
  凹在 +Z 距3（半径内）   格数=  5  +X= 0 -X= 0 +Z= 4 -Z= 0   ★塌成单行
  凹在 -X 距3（半径内）   格数=  5  +X= 0 -X= 4 +Z= 0 -Z= 0   ★塌成单行
  凹在 +X 距7（半径外）   格数=114  +X=50 -X=49 +Z=49 -Z=49   四向 ✓
```

**结论：缺陷成立，且比用户描述更严重**——不只是"少三个方向"，
而是**整个水池从 113 格塌成 5 格（一条 4 格单行）**，且方向随凹坑方位走。

同时PM 独立验证了他的**排除性论证**（这条比结论本身重要）：
崖边场景下两语义结果相同（`E=2 W=0 S=0 N=0`）⇒ T-F1 的崖边证据**确实无法区分**
"硬门控"与"偏好"两种语义 ⇒ **该证据本身编码了被质疑的语义**。
**技术工这条论证成立，这是本轮最有价值的方法论产出。**

## D-8 wiki 快照是否入库：**不入库，但建立可复核替代**

技术工提出一个真缺口：不入库则行号锚点只在报告与本机有效，后续复核者无法查证。

**裁决：不入库**（`docs/04` 红线 4：不得逐字复制 wiki 文本，CC BY-NC-SA 且 NC 禁商用、SA 传染）。

**替代方案（即可复核性解法）**：
- 引用一律用**规范 wiki URL + 访问日期 + 章节名**，不用本地行号
  （行号会随 wiki 编辑漂移，URL 不会）；
- 数值若必须留档，以**"数值 + 来源 URL + 访问日期"**形式写进 `docs/research/`，
  不转录段落；
- PM 已在 T-R1/T-F1 两轮使用 `curl "?action=raw"` 取证，**该手法固化进 `docs/05`**。

⇒ 结论：**行号锚点不是可复核性的好载体，URL + 日期才是。** 这个缺口用改引用方式解决，
不是用入库解决。
