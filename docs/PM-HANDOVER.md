## 2. 项目是什么

C++20 + CMake 的**类 Minecraft 体素沙盒**。在**公开可观察**的玩法/机制/手感/内容组织上
对齐 MC JE，但**代码与资产 100% 原创**。

**红线（`docs/04`，不可协商）**：不复制 MC 的代码、纹理、音效、名称、商标；
禁止反编译、禁止 MCP/Yarn 映射、禁止逐字复制 Minecraft Wiki 文本（CC BY-NC-SA）；
调研文档只记数值/公式/来源 URL/访问日期。

**★ 最重要的方法论（血泪换来的，见 `docs/05 §3`）**：

> **凡判定"与原版不一致"（即缺陷），必须先取得原版基准。**
> (a) 原版实机/机器人读数 —— 最强；(b) 可复核的公开来源（正文 + URL + 日期）；
> (c) **用户观感 —— 只能提出怀疑，不能定性**。没有 (a)(b) 一律写"**待校准**"。

**协作模式**：用户是**唯一转发者**。PM 产出自包含卡面（落 `docs/tasks/T<ID>.md`）
→ 用户把「对话底座 + 卡面绝对路径」转给独立对话 → 开发者/美术总监执行并落报告
→ 用户回贴简短版 → PM 读报告 + **独立复现** → 合并 + 写裁决（`T<ID>.ruling.md`）。

## 6. 环境陷阱（每条都踩过，代价很高）

### 6.1 构建与验证
- **禁止让验证副本与主仓共享 `FETCHCONTENT_BASE_DIR`**。副本若指向主仓 `build/_deps`，
  CMake 会**就地重写**主仓依赖树 ⇒ 主仓构建挂掉（特征：退出码非 0 但 `grep -c error:` 为 0）。
  ⇒ **worktree 一律不设该变量**，让它自行 configure（实测 75 s 通过）。
- **构建命令不要接管道**：`cmd | tail` 的退出码是 tail 的，会把失败显示成成功。
  要判成败：`cmd > log 2>&1; echo $?`。
- **PM 验收要从零 configure + build**（新建 `/tmp/xxx_verify`），不要复用 `build/`。
  ⚠ **合并后主仓 `build/` 仍是旧二进制**——必须先 `cmake --build build` 再 `ctest`，
  否则跑出来的数是合并前的（**曾把 410 误当 422 的结果**）。
- 可执行文件在 **`build/opencraft`**；实际启动是 **`cd build && ./opencraft`**
  （`saves/` 落在 `build/` 下，`assets/` 走 `<cwd>/../assets`）。
- `clang-format` 用 **CLT 的 17**，不是 brew 的 23（后者把未改动文件也判违规）。

### 6.2 worktree 纪律（`docs/05 §6`）
- 根目录固定 `/Users/happy/Desktop/opencraft_worktree/`。
- **所有 Read/Edit/Write 必须用 worktree 绝对路径**——写错主仓会让
  "构建通过 + 测试全绿（旧代码）"完全掩盖。判据：两树 `git status` 一脏一净。
- 验收后 PM 清理：`git worktree remove <dir>`（分支保留）。
  删前必查：`git status --porcelain` 为空 + 已 merged main。
- **同名 worktree 会撞车**：T-M2 遗留了一个 `T-M2-mob-ai`（分支名 `taskT-M2` 拼写异常），
  已合入但用户未授权删除，**保留未动**（如需清理先问用户）。

### 6.3 写卡面
- **引用 `file:line` 前必须现数**（`wc -l` / `grep -n`）。**行号会因后续卡移位**——
  T-B1 卡面初稿引用了 `research/12 §6.6` 写的 `main.cpp:734`，实际已移到 **660/687**
  （T-D45/T-A2 合并所致）。**PM 已多次复发此类错误。**
- **卡面数字须核出处与基准**：例：瓦片数按 `registry.size()`=21（含 air），
  **不是** `register_block` 调用次数 20——错用会多算 3 个瓦片。
- **白名单自洽**：列了一边的 `CMakeLists.txt` 就必须列另一边
  （T-D45 卡面列了 `tests/` 却漏 `game/client/`，逼得开发者写成 header-only）。
- **过程垃圾不得入仓**：证据目录只收最终产物（截图/日志/复跑脚本源码），
  不收 `__pycache__/`、`*.pyc`、临时 PSD、中间稿。
- 验收标准与白名单不得相交；路径写完整绝对路径（`~` 不行）；
  卡面先落 `docs/tasks/T<ID>.md` 再派发；**卡面正文不改**，修订走「变更记录」或裁决。

### 6.4 验收（PM 的核心工作）
- **不采信自述，一律独立复现。** 建干净检出、从零 configure+build、自己写探针。
- **★ 装置必须先自证能分辨两棵树**——否则"结果相同"可能只是跑错了代码。
  实例手法：比 `nm` 符号（`asset_atlas` 在新树有、旧树无）、比源码行数（257 vs 300）。
- **★ 反向对照**：只证明"变了"不够，要证明"**确实因此而变**"。
  实例：T-A2 放品红 PNG ⇒ 只有 tile 4 变（`dirt id 1 × 3 + side 1 = 4`），
  **证明"空目录等价"不是"加载没跑"的假象**。
- **★ 美术卡的生效判据三要素（`docs/05 §3.1` 第 12 条）**：① 启动日志计数
  （`atlas: N/63`，文件名写错是静默回退）② 同机位逐像素差异 ③ **一个"应当没变"的对照组**。
- **★「资产已落盘」≠「玩家能看见」（第 13 条）**：T-A4 主动自曝 `cobblestone`/`sandstone`
  的物品无任何获得途径 ⇒ 贴图合格但游戏内不可达（登记 T-D53）。
- **反解核对**：美术卡用 `tile = block_id × 3 + slot` 反解变化瓦片，能抓出"文件放错方块"。
- **「已实现」≠「可达」**；**「测试夹具成立」≠「生产路径可达」**（T-D17 教训）。
- 开发者**自我纠正**与**主动上报卡面缺陷**应记功并制度化。

### 6.5 GUI / 实机取证（`docs/05 §3.1`，13 条）
- **键盘注入必须 HID 层**（`CGEventCreateKeyboardEvent` + `CGEventPost`，脉冲 86–87 ms）；
  **禁用 `osascript key code`**（2–5 ms 短于每帧轮询 ≈11 ms，必丢）。
- **HID 在本机不稳定**（会话相关）：把决定性场景放在注入生效窗口内，
  或**改写游戏自己写出的存档**（T-D4/T-A4 用过，产品代码零改动）。
- 窗口号**按 PID + 尺寸反查**（按名匹配会命中死窗口）；激活+注入+截图须同一进程；
  `Ctrl+Space` 被系统吞掉；`screencapture` 对非前台窗口返回**旧表面**。
- **渲染/UI 类缺陷单测覆盖不到，必须实机**（T-E1 的掉落物被压到地面以下、
  T-I2 的求值顺序崩溃，单测全绿但画面错/直接崩）。
- **判据**：相机静止时**连续两帧逐像素完全相同** ⇒ 画面里没有东西在动。
- **合成鼠标移动严重非线性**（30 px 可打到 89° 钳位）⇒ 瞄准用潜行的水平视线。

### 6.8 ★ 关于"我的工具说没有"这件事（第三次复发，最重要）
**"没找到"不等于"不存在"。** 三次同型事故：
1. **T-R2**：grep `"2L+7"` 零命中 ⇒ 误判文档缺该公式（实为文档写 `2×level+7`）
2. **T-F1**：探针只证明"OpenCraft 现在是 X" ⇒ 误判"原版不是 X"（后被机器人实测推翻）
3. **T-R3**：curl 官网**根页**（4326 字节 JS 框架）grep 零命中 ⇒ 误判"许可不存在"
   （真内容在 `mv_main.html` 64188 字节，研究员推翻了我）

⇒ **规则**：凡得出"未核到/缺失/不存在"的结论，落笔前必须
① 换 ≥2 种检索路径（换 URL、换关键词、换页面层级、注意 JS 动态加载）
② 区分"**这个 URL 404**"与"**这个信息不存在**"
③ 在结论里写明"用什么方式核过、核了几次"
④ 宁可写"核过 N 个路径未找到，待证"，也不要写"不存在"。
