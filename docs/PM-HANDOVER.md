## 2. 项目是什么

OpenCraft：C++20 + CMake 的**类 Minecraft 体素沙盒**。
在**公开可观察**的玩法/机制/手感/内容组织上对齐 Minecraft Java Edition，
但**代码与资产 100% 原创**。

**红线（docs/04，不可协商）**：不复制 MC 的代码、纹理、音效、名称、商标；
禁止反编译、禁止 MCP/Yarn 映射、禁止逐字复制 Minecraft Wiki 文本（CC BY-NC-SA）；
调研文档**只记数值/公式/来源 URL/访问日期，禁止粘贴反编译源码片段**；伪代码须自撰。

**协作模式**：用户是**唯一转发者**。PM 产出自包含卡面 → 用户复制到独立开发者对话执行
→ 开发者报告由用户回贴 → PM 验收合并。**开发者对话冷启动、无共享记忆**，
所以卡面必须自包含（目标/白名单/接口契约/规格依据/验收标准）。

## 4. ⚠ 最重要的遗留：T-D8 实机不可达（务必读完）

**step-assist 已实现且 203/203 单测全绿，但真实客户端里永远不触发。**

> **🔄 第二任 PM 更正（2026-09-15）：上面这段定性是错的，请以本节末尾为准。**
> 原文把原因归为「`WorldSource` 未覆盖 `shape_top_at`」，并据此登记 T-D17。
> 第二任复核代码后判定：**这不是适配器缺陷。**

**更正后的事实**：

```cpp
// engine/physics/include/opencraft/physics/block_source.hpp:70
virtual double shape_top_at(int wx, int wy, int wz) const {
    return shape_at(wx, wy, wz) != BlockShape::Empty ? 1.0 : 0.0;   // 实心 → 1.0
}
```

在一个**只有完整方块**的世界里，实心方块的顶面高度**就是 1.0**，默认实现完全正确。
而 `BlockRegistry::create_default()`（`engine/voxel/src/block_registry.cpp:24-47`）注册的
20 个方块**全是整方块**（水是非固体液体）。**世界里根本不存在 ≤0.6 的高差**
⇒ step-assist 无事可做。

- ❌ 原 T-D17（「给 WorldSource 接上钩子」）**接了也返回 1.0，行为一字节不变**
  ⇒ 该卡**不可验收，已作废**。
- ✅ 真因是**内容缺口**：需要半砖/地毯/床这类部分高度方块。
- 结论「**不得对外声称自动上台阶已可用**」**依然成立**，但理由改为
  「**世界里没有任何 ≤0.6 的方块可踩**」。
- 重定方向：「部分高度方块地基」（BlockDef 碰撞高度 + 半高网格化 + 图集 + 放置/选取），
  属 M2 内容类，降级待排。

**教训（两层，均已入 lesson）**：

1. 验收必须区分**「已实现」与「可达」**（原 lesson `lsn_9c0fa17daf24dae7` 继续有效）。
2. ★ 新增：**「缺陷」也可能被误判类型**。这次把"内容缺口"误判为"适配器缺陷"，
   代价是差点派一张白做的卡、并可能再次产出假的「已修复」结论。
   **定位到"某个钩子没接"时，先问：接上之后返回值会不会有变化？**
   若答案是否定的，根因在别处。

## 7. 环境陷阱（每条都踩过，代价很高）

### 7.1 构建
- **禁止让验证副本与主仓共享 `FETCHCONTENT_BASE_DIR`**。副本若指向主仓 `build/_deps`，
  CMake 会**就地重写**主仓依赖构建树 ⇒ 主仓构建挂掉。
  特征：退出码非 0 但 `grep -c "error:"` 为 0（make 规则缺失，不是编译错误），极易误判为回归。
  正确做法：副本**不设**该变量让它自己 configure，或复制一份**专用**缓存（永不回指主仓）。
  → **PM 踩过两次**，lesson `lsn_408ee6b6fe11e1fc`。
- 验证用干净检出：`git archive <branch> | tar -x -C /tmp/x`（天然不含 build/）。
  比 `cp -a` 后 `rm -rf build` 可靠——后者还会遇到 CMakeCache 指向旧源路径。
- **构建命令不要接管道**：`cmd | tail` 的退出码是 tail 的，会把失败显示成成功。
  要判成败：`cmd > log 2>&1; echo $?` 或搜 `error:`。
- 可执行文件在 **`build/opencraft`**（不是 `build/game/client/build/...`，后者不存在）。
- configure 首次约 70 s（依赖已缓存时）。

### 7.2 写卡面
- **引用代码行号/符号前，必须确认它存在于【卡面指定的基线分支】**。
  PM 曾读 T-D8 worktree 却当作 main 写进 T-D13 卡面，导致该卡在 main 上无法复现要修的现象，
  开发者开工即阻塞。核对四条：`wc -l` / `sed -n Np` / `git grep <sym> main` / `git log main..<branch>`。
  → lesson `lsn_8522f0d3f47c957d`
- **卡面给的数值型实现建议要先做稳定性验算**。PM 建议的半隐式欧拉在 30 fps 发散
  （过冲 +8446 格），60/144 fps 却正常；开发者改用解析解才对。
- **发卡前自查**：验收标准与白名单不相交；路径写完整绝对路径（不用 `~`）；
  卡面先落 `docs/tasks/T<ID>.md` 再派发。

### 7.3 验收
- **「已实现」≠「可达」**（见 §4）。
- **重生成黄金值时，覆盖率比数值 diff 更重要**：逐 leg 核对旧快照覆盖的行为是否仍被覆盖。
  曾有"疾跑粘滞致普通跳变疾跑跳、越过坑内水面，摔落覆盖 hp 13→20"被预期漂移掩盖。
- **PM 独立复现数值，不采信自述**（开发者报告的数值通常是准的，但口径可能不同）。
- 开发者**自我纠正**与**主动上报卡面缺陷**应记功并制度化（T-D8/T-D13 各有两处）。

### 7.4 GUI 验收
- 脚本化键盘**必须 HID 层**（`CGEventCreateKeyboardEvent` + `CGEventPost(kCGHIDEventTap)`，
  脉冲 86–87 ms）；**禁用 `osascript key code`**（脉冲 2–5 ms，短于每帧 ~11 ms 轮询，必丢）。
- 窗口号**按 PID 反查**（按名匹配会命中死窗口）；激活+注入+截图须同一进程；
  `Ctrl+Space` 被系统吞掉。

### 7.5 agentmemory 工具限制
- `memory_action_update` **只能改 status/priority/result**；title/description 建卡后不可改
  （返回 success 但字段静默不变）→ 写错只能 cancel + 重建。
- `requires` **只认 `act_` ID 且建卡后不可补**。
- `memory_slot_*` 在该后端持续 500，不用。
- ZCode 下无 lifecycle hooks（记忆不自动注入）。
- `memory_snapshot_create` 未启用 → 用 `git tag` 替代。

### 7.6 对外表述（对用户）
- **禁止编造上下文百分比**（第一任曾报 95% 实际 34%）。只报"结构上是否到安全压缩点"，
  需要数字就问用户。
- 未做可达性验证前，**不得**说"X 已修复"，只能说"X 已实现且单测通过"。
